## 1. 알고리즘이란?

### 알고리즘(Algorithm)

**알고리즘(algorithm)**은 주어진 문제를 해결하기 위한 **단계적인 절차**이다.

컴퓨터에서는 특정한 일을 수행하기 위해 여러 명령어를 사용하므로 알고리즘을 **문제를 해결하기 위한 명령어들의 집합**이라고 볼 수도 있다.

중요한 점은 알고리즘 자체는 특정 프로그래밍 언어에 종속되지 않는다는 것이다. 같은 알고리즘을 C, Java, Python 등 서로 다른 언어로 구현할 수 있다. 

### 알고리즘의 조건

단순히 명령어를 나열했다고 해서 모두 알고리즘이 되는 것은 아니다. 알고리즘은 다음 조건을 만족해야 한다.

| 조건 | 의미 |
| --- | --- |
| 입력(Input) | 외부에서 0개 이상의 입력을 받을 수 있음 |
| 출력(Output) | 하나 이상의 결과를 출력해야 함 |
| 명확성 | 각 명령의 의미가 명확해야 함 |
| 유한성 | 무한히 반복되지 않고 반드시 종료되어야 함 |
| 유효성 | 모든 명령이 실제로 수행 가능한 연산이어야 함 |
| 언어 독립성 | 특정 프로그래밍 언어에서만 의미가 있는 절차가 아니어야 함 |

입력은 없는 알고리즘도 존재할 수 있지만 **출력은 반드시 하나 이상 존재해야 한다.** 또한 `0으로 나누기`처럼 수행할 수 없는 명령이나 무한 반복되는 절차는 올바른 알고리즘이 아니다. 

---

### 알고리즘의 기술 방법

알고리즘은 크게 네 가지 방법으로 표현할 수 있다.

| 표현 방법 | 특징 | 장점 | 단점 |
| --- | --- | --- | --- |
| 자연어 | 한국어·영어 등으로 설명 | 쉽고 자유롭게 작성 가능 | 의미가 모호해질 수 있음 |
| 흐름도(Flowchart) | 도형과 화살표로 절차 표현 | 실행 흐름을 정확하고 시각적으로 파악 가능 | 알고리즘이 길어지면 복잡해짐 |
| 프로그래밍 언어 | 실제 코드로 표현 | 직접 실행 가능 | 언어 문법 때문에 핵심 알고리즘이 복잡해 보일 수 있음 |
| 유사코드(Pseudo-code) | 자연어와 코드의 중간 형태 | 문법에 얽매이지 않고 알고리즘 자체에 집중 가능 | 직접 실행할 수 없음 |

예를 들어 세 숫자 `a, b, c` 중 최댓값을 찾는 알고리즘의 핵심은 간단하다.

1. `a`를 최댓값으로 정한다.
2. `b`가 현재 최댓값보다 크면 최댓값을 `b`로 바꾼다.
3. `c`가 현재 최댓값보다 크면 최댓값을 `c`로 바꾼다.
4. 최댓값을 반환한다.

---

### 자연어 표현

사람이 사용하는 언어로 알고리즘을 설명하는 방법이다.

작성하기 쉽고 자유롭지만 **문장의 의미가 애매해질 수 있다는 단점**이 있다. 따라서 각 단계가 명확하게 해석되도록 작성해야 한다.

---

### 흐름도(Flowchart)

알고리즘의 실행 절차를 **도형과 화살표**로 나타내는 방법이다.

조건에 따라 실행 흐름이 어떻게 달라지는지 시각적으로 확인하기 쉽고 절차를 정확하게 표현할 수 있다. 반면 알고리즘이 길어질수록 그림이 복잡해진다는 단점이 있다.

{: .study-diagram }

---

### 특정 프로그래밍 언어 표현

C, Java, Python 등의 실제 프로그래밍 언어로 알고리즘을 작성하는 방법이다.

가장 큰 장점은 **작성한 알고리즘을 바로 실행하고 결과를 확인할 수 있다는 것**이다.

하지만 변수 선언, 자료형, 괄호 등 각 언어의 문법을 정확하게 따라야 하므로 문제 해결 절차와 직접 관계없는 코드까지 포함될 수 있다. 이 때문에 알고리즘의 핵심 아이디어가 오히려 잘 보이지 않을 수 있다.

---

### 유사코드(Pseudo-code)

**유사코드(pseudo-code)**는 자연어보다 체계적이지만 실제 프로그래밍 언어보다는 문법이 자유로운 표현 방법이다.

실제 코드처럼 `if`, `for`, `return` 등을 사용하면서도 자료형 선언이나 엄격한 문법 등은 생략할 수 있어 **알고리즘의 핵심 로직을 표현하기 좋다.**

예를 들어 세 숫자의 최댓값을 찾는다면 다음과 같은 구조가 된다.

```text
max ← a
if b > max then max ← b
if c > max then max ← c
return max
```

유사코드에서는 `←`를 대입 연산자로 사용할 수 있다.

---

### 파이썬을 이용한 표현

Python은 문법이 비교적 간결하기 때문에 유사코드와 실제 코드의 모습이 비슷하다.

```python
def find_max(a, b, c):
    max_value = a

    if b > max_value:
        max_value = b

    if c > max_value:
        max_value = c

    return max_value
```

유사코드처럼 간결하게 알고리즘을 표현하면서 **실제로 실행하여 결과까지 확인할 수 있다는 장점**이 있다. 

💡 **코테 포인트**

코딩테스트 문제를 처음부터 코드로 작성하려고 하면 막히기 쉽다. 먼저 문제를 다음처럼 **유사코드 수준의 단계로 분해한 뒤 Python으로 옮기는 방식**이 유용하다.

`입력 확인 → 필요한 값 저장 → 반복/조건 처리 → 결과 반환`

즉, **문제 해결 방법을 만드는 것 = 알고리즘 설계**, **그 방법을 Python 문법으로 옮기는 것 = 구현**이라고 구분해서 생각하면 된다.

## 2. 알고리즘의 성능 분석

같은 문제를 해결하는 알고리즘이 여러 개라면 어떤 알고리즘이 더 효율적인지 비교해야 한다.

가장 중요한 기준은 **연산량과 메모리 사용량**이다.

| 기준 | 의미 |
| --- | --- |
| 시간 효율성 | 얼마나 적은 연산으로 문제를 해결하는가 |
| 공간 효율성 | 얼마나 적은 메모리를 사용하는가 |

가장 이상적인 알고리즘은 시간과 공간을 모두 적게 사용하는 알고리즘이지만 두 조건을 동시에 만족시키기 어려운 경우도 있다. 일반적으로는 **시간 효율성을 더 중요하게 고려**한다.

---

## 실행 시간 측정 방법

알고리즘의 시간 효율성을 확인하는 가장 직접적인 방법은 **실제 실행 시간을 측정하는 것**이다.

Python에서는 `time` 모듈을 이용할 수 있다.

```python
import time

start = time.time()
test_algorithm(input_data)
end = time.time()

print(end - start)
```

실행 전 시간을 저장하고 실행 후 시간에서 빼면 실제 실행 시간을 구할 수 있다.

하지만 실행 시간만으로 알고리즘의 성능을 비교하는 데에는 한계가 있다.

- 알고리즘을 실제로 구현해야 한다.
- 동일한 하드웨어에서 실행해야 정확한 비교가 가능하다.
- 프로그래밍 언어와 운영체제 등의 실행 환경에 따라 속도가 달라진다.
- 어떤 입력 데이터를 사용했는지에 따라 결과가 달라질 수 있다.

따라서 실행 시간이 1초라고 해서 그 알고리즘 자체가 항상 빠른 알고리즘이라고 판단할 수는 없다.

---

## 복잡도 분석(Complexity Analysis)

실제로 프로그램을 실행하지 않고 알고리즘 자체를 분석하여 성능을 평가하는 방법을 **복잡도 분석(complexity analysis)**이라고 한다.

복잡도는 크게 두 종류로 나뉜다.

| 종류 | 의미 |
| --- | --- |
| 시간 복잡도(Time Complexity) | 입력 크기가 증가할 때 필요한 연산량이 얼마나 증가하는가 |
| 공간 복잡도(Space Complexity) | 입력 크기가 증가할 때 필요한 메모리가 얼마나 증가하는가 |

코딩테스트에서는 특히 **시간 복잡도**가 중요하다. 

---

### 입력 크기 n

복잡도를 분석하려면 먼저 **입력의 크기 `n`이 무엇인지** 정해야 한다.

예를 들어 리스트를 처리하는 알고리즘이라면 보통 **n = 리스트에 들어 있는 원소의 개수** 가 된다.

문자열 문제라면 문자열 길이, 그래프 문제라면 정점이나 간선의 수 등이 입력 크기가 될 수 있다.

💡 **코테 포인트**

복잡도를 계산하기 전에 가장 먼저 해야 할 질문은

> **이 문제에서 n이 무엇인가?**
> 

이다.

---

## 연산 횟수로 성능 비교하기

1부터 n까지 합을 구하는 두 가지 방법을 비교해보자.

### 방법 1: 반복문 사용

`1 + 2 + 3 + ... + n`을 반복문으로 하나씩 더한다.

반복문 내부의 연산이 n번 실행되므로 입력이 커질수록 필요한 연산 수도 함께 증가한다.

복잡도 함수는 연산을 세는 방법에 따라

**T(n) = 2n + 1**

과 같이 표현할 수 있다.

### 방법 2: 공식 사용

1부터 n까지의 합 공식

**n(n + 1) / 2**

을 이용하면 n의 크기와 관계없이 일정한 수의 연산만 수행하면 된다.

복잡도 함수는

**T(n) = 4**

와 같이 일정하다.

따라서 중요한 것은 컴퓨터에서 정확히 몇 초 걸리는지가 아니라

> **n이 증가할 때 연산량이 어떻게 증가하는가**
> 

이다.

이것이 복잡도 분석의 핵심이다.

---

## 복잡도의 점근적 표기

복잡도 함수가

**T(n) = 8n² + 2n + 17**

이라면 n이 매우 커질수록 `n²`의 영향이 가장 커지고 `2n`, `17`의 영향은 상대적으로 작아진다.

따라서 복잡도를 표현할 때는 보통

1. **가장 빠르게 증가하는 최고차항만 남기고**
2. **상수 계수는 제거한다.**

예를 들어

| 복잡도 함수 | 단순화 |
| --- | --- |
| `2n + 1` | `n` |
| `8n² + 2n + 17` | `n²` |
| `65536n + 2000000` | `n` |
| `0.000001n³` | `n³` |

이처럼 정확한 연산 횟수가 아니라 **입력 크기가 증가할 때 연산량이 증가하는 속도**를 표현하는 방법을 **점근적 표기(asymptotic notation)**라고 한다.

💡 **코테 포인트**

시간 복잡도에서 상수와 낮은 차수의 항을 버리는 이유를 이해해야 한다.

예를 들어

**3n² + 100n + 500**

은 `O(n²)`이다.

n이 매우 커지면 결국 `n²`이 전체 증가 속도를 결정하기 때문이다.

---

## 빅오(Big-O) 표기법

**Big-O**는 알고리즘 복잡도의 **상한(upper bound)**을 나타낸다.

`O(g(n))`은 증가 속도가 `g(n)`과 같거나 더 낮은 복잡도 함수들을 포함한다.

예를 들어

**3n² + 4n ∈ O(n²)**

라고 표현할 수 있다.

n이 커질수록 `n²` 항이 전체 증가 속도를 결정하기 때문이다. 

알고리즘 문제에서는 일반적으로 **최악의 상황에서도 어느 정도의 시간 안에는 끝나는가**가 중요하기 때문에 Big-O가 가장 많이 사용된다.

---

## 빅오메가(Big-Ω) 표기법

**Big-Omega(Ω)**는 복잡도의 **하한(lower bound)**을 나타낸다.

즉, 알고리즘이 아무리 빠르게 처리되더라도 적어도 이 정도의 연산은 필요하다는 의미이다.

예를 들어 어떤 복잡도가 `Ω(n²)`이라면 최소한 `n²`에 비례하는 증가 속도를 갖는다는 뜻이다. 

---

## 빅세타(Big-Θ) 표기법

**Big-Theta(Θ)**는 상한과 하한이 동일한 경우 사용한다.

즉, 알고리즘의 증가 속도를 정확하게 나타낼 수 있을 때 사용한다.

예를 들어

**3n² + 4n ∈ Θ(n²)**

이다.

| 표기 | 의미 |
| --- | --- |
| `O(g(n))` | 상한 |
| `Ω(g(n))` | 하한 |
| `Θ(g(n))` | 상한과 하한이 같은 증가율 |

![빅오·빅오메가·빅세타의 상한과 하한](/assets/img/posts/algorithm-chapter5/asymptotic-bounds.png)
{: .study-diagram }

시간 복잡도를 정확하게 계산할 수 있다면 Θ를 사용할 수 있고, 일반적인 알고리즘 분석에서는 최악의 상황을 고려하기 위해 Big-O가 많이 사용된다.

---

## 자주 사용하는 시간 복잡도

대표적인 시간 복잡도를 빠른 순서대로 나열하면 다음과 같다.

**O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(3ⁿ) < O(n!)**

![입력 크기에 따른 시간복잡도 증가율](/assets/img/posts/algorithm-chapter5/time-complexity-growth.png)
{: .study-diagram }

### O(1) — 상수 시간

입력 크기 n과 관계없이 연산 횟수가 일정하다.

예: 리스트에서 인덱스로 특정 원소 하나 접근

`A[3]`

n이 10이든 100만이든 한 번의 접근이면 된다.

---

### O(log n) — 로그 시간

문제의 크기가 반복할 때마다 일정한 비율로 감소하는 형태이다.

대표적으로

**n → n/2 → n/4 → n/8 → ...**

처럼 절반씩 줄어드는 경우가 있다.

예를 들어 n을 계속 2로 나누다가 1이 되면 종료되는 반복문은 `O(log n)`으로 볼 수 있다.

💡 **코테 포인트**

반복문이라고 무조건 `O(n)`은 아니다.

`i += 1`처럼 하나씩 증가하면 보통 `O(n)`이지만, `n //= 2`처럼 입력 자체가 반복마다 절반으로 감소한다면 `O(log n)`이 될 수 있다.

---

### O(n) — 선형 시간

입력 크기 n에 비례하여 연산량이 증가한다.

예: 리스트 전체 순회

`for x in A:`

원소가 n개라면 n개를 확인해야 하므로 `O(n)`이다.

---

### O(n log n)

`O(n)`과 `O(log n)`이 결합된 형태이다.

뒤에서 배우는 효율적인 정렬 알고리즘에서 자주 등장하는 중요한 복잡도이다.

---

### O(n²) — 이차 시간

입력 크기가 n일 때 연산량이 n²에 비례한다.

대표적인 형태는 **이중 반복문**이다.

```python
for i in range(n):
    for j in range(n):
        # O(1) 작업
        pass
```

바깥쪽 n번 × 안쪽 n번이므로 `O(n²)`이다.

---

### O(n³) — 삼차 시간

3중 반복문처럼 n에 비례하는 작업이 세 번 중첩된 형태에서 나타날 수 있다.

n이 커질수록 `O(n²)`보다 훨씬 빠르게 연산량이 증가한다.

---

### O(2ⁿ), O(3ⁿ) — 지수 시간

n이 하나 증가할 때마다 필요한 연산량이 매우 빠르게 증가한다.

입력이 수십 개 정도만 되어도 연산량이 매우 커질 수 있다.

---

### O(n!) — 팩토리얼 시간

가능한 모든 순서를 확인하는 문제 등에서 나타날 수 있다.

n이 조금만 증가해도 연산량이 폭발적으로 증가한다.

---

### 입력 크기와 시간 복잡도

시간 복잡도는 단순히 외울 것이 아니라 **입력 크기 n과 함께 판단해야 한다.**

예를 들어 `O(n²)` 알고리즘이 있다고 해도 n이 10이라면 약 100번 수준의 연산이지만, n이 100,000이라면 약 100억 번 수준으로 증가한다.

따라서 코딩테스트에서는 문제를 읽으면

**입력 제한 확인 → 가능한 시간 복잡도 판단 → 알고리즘 선택**

순서로 접근하는 것이 중요하다.

---

## 최선, 최악, 평균적인 효율성

같은 알고리즘이라도 입력 데이터의 구성에 따라 실행 시간이 달라질 수 있다.

이를 세 가지 경우로 나누어 분석한다.

### 최선의 경우(Best Case)

알고리즘의 실행 시간이 **가장 적게 걸리는 입력**이다.

### 평균적인 경우(Average Case)

가능한 입력과 각 입력이 발생할 확률을 고려하여 계산한 **평균 실행 시간**이다.

정확하게 계산하기 어려운 경우가 많다.

### 최악의 경우(Worst Case)

알고리즘의 실행 시간이 **가장 오래 걸리는 입력**이다.

알고리즘 분석에서는 최악의 경우가 가장 중요하게 사용된다. 어떤 입력이 들어오더라도 최대 어느 정도의 시간이 필요한지를 판단할 수 있기 때문이다.

---

## 예제 1. 리스트에서 최댓값 찾기

리스트에서 최댓값을 찾으려면 모든 원소를 확인해야 한다.

```python
def find_max(A):
    max_value = A[0]

    for value in A[1:]:
        if value > max_value:
            max_value = value

    return max_value
```

리스트의 크기를 `n`이라고 하면 비교 연산은 n에 비례하여 반복된다.

따라서

**T(n) = n**

이고 시간 복잡도는

**O(n)**

이다.

여기서 중요한 점은 리스트의 **내용이 달라져도 모든 원소를 확인한다는 것**이다.

따라서 최댓값이 앞에 있든 뒤에 있든 반복 횟수가 달라지지 않는다. 최선·평균·최악을 구분할 필요 없이 항상 `O(n)`이다.

---

## 예제 2. 리스트에서 특정 값 찾기

리스트 `A`에서 `key`를 앞에서부터 순서대로 찾는 방법을 **순차 탐색(Sequential Search)**이라고 한다.

```python
def find_key(A, key):
    for i in range(len(A)):
        if A[i] == key:
            return i

    return -1
```

값을 발견하면 즉시 종료하기 때문에 **key가 어디에 있는지에 따라 연산 횟수가 달라진다.**

![순차 탐색의 최선·평균·최악 사례](/assets/img/posts/algorithm-chapter5/sequential-search-cases.png)
{: .study-diagram }

### 최선의 경우

찾는 값이 리스트의 첫 번째에 있다.

비교 횟수 = 1

**O(1)**

### 최악의 경우

찾는 값이 리스트의 마지막에 있거나 리스트에 존재하지 않는다.

비교 횟수 = n

**O(n)**

### 평균적인 경우

각 위치에서 key가 발견될 확률이 동일하다고 가정하면 평균 비교 횟수는

**(1 + 2 + ... + n) / n**

이고,

**= n(n + 1) / 2n**

**= (n + 1) / 2**

가 된다.

상수와 낮은 영향을 제거하면

**O(n)**

이다.

따라서 순차 탐색은 다음과 같이 정리할 수 있다.

| 경우 | 비교 횟수 | 시간 복잡도 |
| --- | --- | --- |
| 최선 | 1 | O(1) |
| 평균 | (n+1)/2 | O(n) |
| 최악 | n | O(n) |

---

## 코딩테스트에서 기억할 내용

### 1. 문제를 보면 입력 크기부터 확인하기

시간 복잡도를 판단하려면 먼저 **n이 무엇인지** 찾아야 한다.

예를 들어 입력 제한이

`1 ≤ N ≤ 100,000`

이라면 `N`이 알고리즘의 입력 크기이다.

그다음 내가 작성하려는 알고리즘이 `O(n)`인지, `O(n²)`인지 판단한다.

---

### 2. 반복문 개수만 보고 복잡도를 판단하지 않기

단순한 반복문 하나는 보통 `O(n)`이다.

하지만 반복마다 문제의 크기가 절반으로 줄어든다면 `O(log n)`이 될 수 있다.

반대로 반복문이 중첩되어 있다면 `O(n²)`, `O(n³)` 등이 될 수 있다.

따라서 **반복문이 몇 개 있는가보다 각 반복문이 몇 번 실행되는가**를 확인해야 한다.

---

### 3. 가장 많이 반복되는 부분 찾기

정확한 연산 횟수를 하나하나 세지 않아도 시간 복잡도를 판단할 수 있다.

예를 들어

**T(n) = 3n² + 5n + 100**

이라면 n이 커질수록 `n²` 항의 영향이 가장 크다.

따라서

**O(n²)**

이라고 판단한다.

즉,

> **가장 빠르게 증가하는 항을 찾는다 → 계수를 제거한다**
> 

가 기본이다.

---

### 4. 순차 실행은 더하고, 중첩 반복은 곱하기

두 반복문이 순서대로 실행된다면

`O(n) + O(n) = O(2n) = O(n)`

이다.

반면 반복문 안에 반복문이 있다면

`O(n) × O(n) = O(n²)`

이 된다.

💡 **코테에서 매우 중요**

**나란히 있으면 더하기, 안에 들어 있으면 곱하기**

라고 먼저 생각하면 복잡도 계산이 쉬워진다.

---

### 5. 조건문이 있다고 무조건 복잡도가 증가하지는 않음

`if` 한 번을 확인하는 것은 일반적으로 `O(1)`이다.

따라서 n번 반복되는 반복문 안에 조건문이 하나 있다고 해서 `O(n²)`이 되는 것이 아니다.

n번 반복하면서 조건을 한 번씩 확인한다면 여전히 **O(n)**이다.

---

### 6. 중간에 return이 있다면 입력에 따라 실행 횟수가 달라질 수 있음

순차 탐색처럼 값을 발견하면 바로 `return`하는 알고리즘은 입력에 따라 실행 시간이 달라진다.

따라서

- 바로 발견 → 최선 `O(1)`
- 마지막에 발견하거나 없음 → 최악 `O(n)`

처럼 나누어 생각할 수 있다.

---

### 7. 코테에서는 보통 최악의 경우를 기준으로 생각하기

특정 입력에서만 빨리 실행되는 것이 아니라 **가장 불리한 입력이 들어와도 제한 시간 안에 실행되어야 한다.**

따라서 특별한 설명이 없다면 먼저 **최악의 경우 시간 복잡도**를 확인하는 습관을 들이는 것이 좋다.

## Chapter 05 핵심 요약

**알고리즘(Algorithm)**

→ 문제를 해결하기 위한 단계적인 절차

→ 특정 프로그래밍 언어와 독립적

**알고리즘 표현 방법**

→ 자연어

→ 흐름도

→ 프로그래밍 언어

→ 유사코드

**성능 평가 기준**

→ 시간 효율성 = 연산량

→ 공간 효율성 = 메모리 사용량

**복잡도 분석**

→ 실제 실행하지 않고 알고리즘의 성능을 분석

→ 시간 복잡도 + 공간 복잡도

**시간 복잡도**

→ 입력 크기 n이 증가할 때 필요한 연산량이 얼마나 증가하는지 분석

**점근적 표기**

→ 정확한 연산 횟수보다 증가 속도에 집중

→ 최고차항을 남기고 계수를 제거

**Big-O**

→ 상한

**Big-Ω**

→ 하한

**Big-Θ**

→ 상한과 하한이 동일

**시간 복잡도 증가 순서**

**O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(3ⁿ) < O(n!)**

**최선(Best Case)**

→ 가장 적은 시간이 필요한 입력

**평균(Average Case)**

→ 가능한 입력을 고려한 평균 실행 시간

**최악(Worst Case)**

→ 가장 많은 시간이 필요한 입력

→ 알고리즘 분석에서 중요

**리스트 최댓값 찾기**

→ 모든 원소 확인

→ **O(n)**

**순차 탐색**

→ 최선 **O(1)**

→ 평균 **O(n)**

→ 최악 **O(n)**

5장의 핵심 흐름은 **알고리즘 설계 → 입력 크기 n 파악 → 반복되는 핵심 연산 찾기 → T(n) 파악 → 증가 속도만 남기기 → Big-O로 시간 복잡도 판단 → 입력 제한에 맞는 알고리즘 선택**이다. 연습문제도 Big-O의 증가 속도 비교, 반복마다 `n = n / 2`가 되는 알고리즘의 복잡도 분석, 4장의 모스 코드 알고리즘 비교를 요구하므로 **복잡도를 직접 계산하고 비교할 수 있는 것**이 5장에서 가장 중요하다.
