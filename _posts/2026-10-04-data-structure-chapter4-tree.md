## 1. 트리란?

### 트리(Tree)

**트리(tree)**는 나무를 거꾸로 뒤집어 놓은 것처럼 생긴 자료구조로, **계층적인 관계를 가진 자료를 표현하는 데 적합한 비선형 자료구조**이다.

예를 들어 회사의 조직도를 생각하면 이해하기 쉽다.

- 사장 → 가장 위에 있는 루트
- 부장 → 사장의 하위 노드
- 팀장 → 부장의 하위 노드
- 직원 → 더 이상 하위 조직이 없는 끝 노드

트리는 운영체제의 파일 시스템, 자료 탐색, 우선순위 큐, 결정 트리 등 다양한 분야에서 사용된다.

---

### 트리 관련 용어

트리를 구성하는 각각의 요소를 **노드(node)**라고 하고, 노드 사이의 연결 관계를 **간선 또는 에지(edge)** 라고 한다.

| 용어 | 의미 |
| --- | --- |
| 루트 노드(root) | 트리에서 가장 높은 곳에 있는 노드 |
| 부모 노드(parent) | 간선으로 직접 연결된 상위 노드 |
| 자식 노드(child) | 간선으로 직접 연결된 하위 노드 |
| 형제 노드(sibling) | 같은 부모를 가진 노드 |
| 조상 노드(ancestor) | 해당 노드에서 루트까지 경로에 존재하는 상위 노드 |
| 자손 노드(descendent) | 해당 노드 아래에 연결된 모든 노드 |
| 단말 노드(terminal, leaf) | 자식이 없는 노드 |
| 비단말 노드 | 하나 이상의 자식을 가진 노드 |
| 노드의 차수(degree) | 해당 노드가 가진 자식의 수 |
| 트리의 차수 | 트리에 존재하는 노드의 차수 중 가장 큰 값 |
| 레벨(level) | 트리의 각 층에 매긴 번호 |
| 트리의 높이(height) | 트리가 가지고 있는 최대 레벨 |

예를 들어 다음 트리가 있다고 하자.

![트리의 노드 관계 예시](/assets/img/posts/tree-chapter4/tree-node-relationships.png)
{: .study-diagram }

A는 루트이고, B·C·D는 A의 자식이다. B의 부모는 A이고, C와 D는 B의 형제이다. E와 F는 단말 노드이다.

또한 모든 노드는 자기 자신을 루트로 하는 하나의 **서브 트리(subtree)**라고 볼 수 있다.

따라서 트리는

> **하나의 루트 + 여러 개의 서브 트리**
> 

로 구성되는 **순환적인(recursive) 구조**이다.

이러한 특성 때문에 트리 알고리즘에서는 **순환호출(재귀)**이 자주 사용된다.

💡 **코테 포인트**

트리 문제가 나오면 재귀를 먼저 떠올려 볼 필요가 있다.

현재 노드에서 문제를 해결하는 방식과 왼쪽/오른쪽 서브 트리에서 문제를 해결하는 방식이 동일하기 때문이다.

---

### 트리의 표현 방법

#### 중첩된 집합

트리를 **서브 트리들의 집합**으로 생각하여 표현할 수 있다.

#### 중첩된 괄호

루트와 서브 트리를 괄호로 묶어서 표현한다.

예를 들어 A가 루트이고 B, C, D가 자식이라면 A를 중심으로 각각의 서브 트리를 괄호로 중첩하여 표현할 수 있다.

문자열 형태로 트리 전체를 표현할 수 있다는 장점이 있지만 구조를 직관적으로 파악하기는 어렵다.

#### 들여쓰기(Indentation)

계층에 따라 들여쓰기를 다르게 하는 방법이다.

파일과 폴더를 보여주는 탐색기의 구조가 대표적인 예이다.

---

### 일반 트리의 표현

자식의 개수에 제한이 없는 트리를 **일반 트리(general tree)**라고 한다.

#### N-링크 표현

차수가 N인 노드가 **N개의 링크를 갖도록 하는 방식**이다.

노드마다 필요한 자식의 수만큼 링크를 가지면 된다.

하지만 각 노드의 자식 수가 다르기 때문에 **노드마다 필요한 링크의 개수가 달라지는 문제**가 있다.

#### 왼쪽 자식-오른쪽 형제 표현

모든 노드가 두 개의 링크만 갖도록 한다.

- `child` → 첫 번째 자식
- `sibling` → 다음 형제

예를 들어 B의 첫 번째 자식이 E이고 다음 형제가 C라면,

- B의 `child` → E
- B의 `sibling` → C

가 된다.

두 개의 링크만으로 임의의 일반 트리를 표현할 수 있지만, 원하는 노드까지 찾아가는 과정이 복잡해질 수 있다.

# 2. 이진 트리

### 이진 트리(Binary Tree)

**이진 트리(binary tree)**는 모든 노드가 **최대 2개의 자식**만 가질 수 있는 트리이다.

즉, 모든 노드의 차수가 2 이하이다.

이때 두 자식은 단순히 자식 두 개가 아니라

- 왼쪽 자식(left child)
- 오른쪽 자식(right child)

으로 **순서가 명확하게 구분된다.**

이진 트리는 일반 트리보다 구조가 제한적이지만 이를 이용해 효율적인 알고리즘을 만들 수 있다.

대표적인 예는 다음과 같다.

- 이진 탐색 트리(binary search tree)
- 힙 트리(heap tree)
- 수식 트리(expression tree)

---

## 이진 트리의 종류

### 포화 이진 트리(Full Binary Tree)

교재에서는 **각 레벨에 노드가 모두 차 있는 이진 트리**를 포화 이진 트리라고 한다.

높이가 `k`라면 전체 노드 수는 **2ᵏ - 1** 이다.

예를 들어 높이가 3이면 2³ - 1 = **7개** 의 노드를 가진다.

노드에 위에서 아래, 왼쪽에서 오른쪽 순으로 번호를 붙이면 루트는 1, 루트의 왼쪽 자식은 2, 오른쪽 자식은 3이 된다.

---

### 완전 이진 트리(Complete Binary Tree)

높이가 k인 트리에서

- 레벨 1 ~ k-1까지 모든 노드가 채워져 있고
- 마지막 레벨은 **왼쪽부터 오른쪽 순서대로** 노드가 채워진

이진 트리를 말한다.

따라서 마지막 레벨이 완전히 채워질 필요는 없지만 **중간에 빈 공간이 있으면 안 된다.**

포화 이진 트리는 완전 이진 트리이지만, 완전 이진 트리가 항상 포화 이진 트리인 것은 아니다.

**힙(heap)**이 완전 이진 트리의 대표적인 예이다.

---

### 균형 이진 트리(Balanced Binary Tree)

**균형 이진 트리 또는 높이 균형 이진 트리(height-balanced binary tree)**는 모든 노드에서

> 왼쪽 서브 트리의 높이와 오른쪽 서브 트리의 높이 차이가 1 이하
> 

인 트리를 의미한다.

어느 한 노드라도 좌우 서브 트리의 높이 차이가 1을 초과하면 균형 이진 트리가 아니다.

![포화·완전·균형 이진 트리 비교](/assets/img/posts/tree-chapter4/binary-tree-types.png)
{: .study-diagram }

그림의 ①은 포화 이진 트리, ②는 완전 이진 트리, ③은 균형 이진 트리의 예이다.

💡 **코테 포인트**

균형이 중요한 이유는 트리의 높이와 탐색량이 밀접하게 관련되기 때문이다.

균형이 잘 잡힌 트리는 높이가 대략 `log N` 수준이지만, 한쪽으로 계속 늘어진 트리는 높이가 `N`까지 커질 수 있다.

---

## 이진 트리의 표현 방법

이진 트리는 크게

1. 배열 구조
2. 연결된 구조

로 표현할 수 있다.

### 배열 구조 표현

포화 이진 트리에서 노드에 붙이는 번호를 그대로 배열의 인덱스로 사용하는 방법이다.

교재에서는 **루트 노드의 인덱스를 1**로 사용한다.

노드 `i`에 대해

| 관계 | 인덱스 |
| --- | --- |
| 부모 | `i // 2` |
| 왼쪽 자식 | `2 × i` |
| 오른쪽 자식 | `2 × i + 1` |

![이진 트리의 배열 인덱스 관계](/assets/img/posts/tree-chapter4/binary-tree-array-index.png)
{: .study-diagram }

따라서 인덱스 3의 노드가 있다면

- 부모 → 1
- 왼쪽 자식 → 6
- 오른쪽 자식 → 7

이 된다.

이 방법은 **포화 이진 트리나 완전 이진 트리에 적합**하다.

반대로 한쪽으로 치우친 경사 트리에서는 배열 중간에 빈 공간이 많이 생기므로 메모리 낭비가 커질 수 있다.

💡 **코테 포인트 — Python에서 0부터 시작하는 배열을 사용할 경우**

Python 리스트는 보통 0부터 사용한다.

0-based 배열에서 노드 `i`의 관계는 다음과 같다.

| 관계 | 인덱스 |
| --- | --- |
| 부모 | `(i - 1) // 2` |
| 왼쪽 자식 | `2 * i + 1` |
| 오른쪽 자식 | `2 * i + 2` |

힙 문제에서 매우 자주 사용되는 공식이다.

---

### 연결된 구조 표현

이진 트리의 노드는 왼쪽과 오른쪽 자식을 가리키는 **두 개의 링크**를 가진다.

교재에서는 이를 `BTNode`로 구현한다.

```python
class BTNode:
    def __init__(self, elem, left=None, right=None):
        self.data = elem
        self.left = left
        self.right = right
```

즉 하나의 노드는 **data + left + right** 로 구성된다.

![이진 트리 노드의 연결 구조](/assets/img/posts/tree-chapter4/binary-tree-linked-node.png)
{: .study-diagram }

앞으로 교재의 이진 트리 연산은 이러한 링크 표현법을 기준으로 설명한다.

# 3. 이진 트리의 연산

## 이진 트리의 표준 순회

**순회(traversal)**란 트리에 존재하는 **모든 노드를 한 번씩 방문하는 것**이다.

선형 자료구조에서는 자료가 일렬로 나열되어 있으므로 순서대로 방문하면 된다.

하지만 트리는 계층 구조이므로 어떤 순서로 방문할 것인지 여러 방법이 존재한다.

이진 트리의 기본적인 순회 방법은 다음 세 가지이다.

| 순회 | 순서 | 의미 |
| --- | --- | --- |
| 전위순회(preorder) | VLR | 루트 → 왼쪽 → 오른쪽 |
| 중위순회(inorder) | LVR | 왼쪽 → 루트 → 오른쪽 |
| 후위순회(postorder) | LRV | 왼쪽 → 오른쪽 → 루트 |

여기서

- V = 현재 루트 방문
- L = 왼쪽 서브 트리
- R = 오른쪽 서브 트리

![전위·중위·후위 순회 결과](/assets/img/posts/tree-chapter4/tree-traversal-orders.png)
{: .study-diagram }

이다.

---

## 전위순회(Preorder)

**V → L → R**

즉,

1. 현재 노드 방문
2. 왼쪽 서브 트리 순회
3. 오른쪽 서브 트리 순회

순서이다.

```python
def preorder(n):
    if n is not None:
        print(n.data, end=' ')
        preorder(n.left)
        preorder(n.right)
```

예를 들어

```
        A
       / \
      B   C
     / \  /
    D  E F
```

라면 전위순회 결과는

**A → B → D → E → C → F**

이다. 

---

## 중위순회(Inorder)

**L → V → R**

즉,

1. 왼쪽 서브 트리 순회
2. 현재 노드 방문
3. 오른쪽 서브 트리 순회

순서이다.

```python
def inorder(n):
    if n is not None:
        inorder(n.left)
        print(n.data, end=' ')
        inorder(n.right)
```

위 트리를 중위순회하면

**D → B → E → A → F → C**

가 된다.

---

## 후위순회(Postorder)

**L → R → V**

즉,

1. 왼쪽 서브 트리 순회
2. 오른쪽 서브 트리 순회
3. 현재 노드 방문

순서이다.

```python
def postorder(n):
    if n is not None:
        postorder(n.left)
        postorder(n.right)
        print(n.data, end=' ')
```

위 트리를 후위순회하면

**D → E → B → F → C → A**

가 된다.

---

## 순회 방법의 선택

순회 순서를 그냥 암기하기보다 **부모와 자식 중 누구를 먼저 처리해야 하는가**를 생각하면 된다.

### 자식보다 부모를 먼저 처리해야 한다

→ **전위순회**

예를 들어 각 노드의 레벨을 계산한다고 하자.

자식의 레벨은

**부모의 레벨 + 1**

이므로 부모를 먼저 처리해야 한다.

### 부모보다 자식을 먼저 처리해야 한다

→ **후위순회**

예를 들어 폴더 전체 용량을 계산하려면 먼저 하위 폴더들의 용량을 알아야 한다.

따라서 자식들을 먼저 계산하고 마지막에 부모를 계산한다.

### 모든 노드를 방문하기만 하면 된다

방문 순서가 중요하지 않은 문제라면 전위·중위·후위 중 어느 것을 사용해도 된다.

💡 **코테 포인트**

전위·중위·후위순회는 모두 **한 방향으로 깊게 내려갔다가 돌아오는 방식**이므로 코딩테스트 관점에서는 **DFS(깊이 우선 탐색)**와 연결해서 이해하면 좋다.

---

## 레벨 순회(Level Order)

레벨 순회는

> 위에서 아래로, 같은 레벨에서는 왼쪽에서 오른쪽으로
> 

노드를 방문한다.

위의 예시 트리에서는

**A → B → C → D → E → F**

순서가 된다.

전위·중위·후위와 달리 **큐(Queue)**를 이용한다.

처리 과정은 다음과 같다.

1. 큐에 루트를 넣는다.
2. 큐에서 노드 하나를 꺼낸다.
3. 해당 노드를 방문한다.
4. 왼쪽 자식을 큐에 넣는다.
5. 오른쪽 자식을 큐에 넣는다.
6. 큐가 빌 때까지 반복한다.

교재의 핵심 구현은 다음과 같다.

```python
def levelorder(root):
    queue = ArrayQueue()
    queue.enqueue(root)

    while not queue.isEmpty():
        n = queue.dequeue()
        if n is not None:
            print(n.data, end=' ')
            queue.enqueue(n.left)
            queue.enqueue(n.right)
```

즉,

> **레벨 순회 = Queue**
> 

라고 기억하면 된다.

💡 **코테 포인트**

레벨 순회는 코딩테스트에서 **BFS(너비 우선 탐색)**에 해당한다.

따라서 트리 문제에서

- 레벨별 처리
- 루트에서의 거리
- 특정 깊이의 노드
- 가장 가까운 조건의 노드

등을 다룬다면 BFS를 떠올려 볼 수 있다.

Python에서는 보통 큐로 `collections.deque`를 사용한다.

![DFS와 BFS 탐색 방식 비교](/assets/img/posts/tree-chapter4/dfs-bfs-comparison.png)
{: .study-diagram }

---

## 전체 노드의 수 구하기

트리는 재귀적인 구조이므로 전체 노드 수도 재귀적으로 구할 수 있다.

핵심 아이디어는

> **전체 노드 수 = 왼쪽 서브 트리 노드 수 + 오른쪽 서브 트리 노드 수 + 1**
> 

이다.

마지막 `+1`은 현재 노드이다.

```python
def count_node(n):
    if n is None:
        return 0

    return count_node(n.left) + count_node(n.right) + 1
```

`None`이면 노드가 없는 공백 트리이므로 0을 반환한다.

---

## 트리의 높이 구하기

높이 역시 재귀적으로 구할 수 있다.

핵심 아이디어는

> **현재 트리 높이 = max(왼쪽 서브 트리 높이, 오른쪽 서브 트리 높이) + 1**
> 

이다.

```python
def calc_height(n):
    if n is None:
        return 0

    hLeft = calc_height(n.left)
    hRight = calc_height(n.right)

    return max(hLeft, hRight) + 1
```

왜 `max()`를 사용할까?

트리의 높이는 **가장 깊은 곳까지의 높이**이기 때문에 왼쪽과 오른쪽 중 더 높은 서브 트리를 선택해야 한다.

---

### 재귀 트리 문제의 기본 패턴

노드 개수와 높이 문제를 비교하면 트리 재귀의 기본적인 구조를 볼 수 있다.

**노드 개수**

`왼쪽 결과 + 오른쪽 결과 + 현재 노드`

**높이**

`max(왼쪽 결과, 오른쪽 결과) + 현재 노드`

즉 트리 문제에서는

> ① 종료 조건은 무엇인가?
> 
> 
> ② 왼쪽 서브 트리의 결과는 무엇인가?
> 
> ③ 오른쪽 서브 트리의 결과는 무엇인가?
> 
> ④ 두 결과를 현재 노드에서 어떻게 합칠 것인가?
> 

를 생각하는 것이 중요하다.

💡 **코테 포인트**

전위·중위·후위 순회와 노드 개수, 높이 계산은 모두 모든 노드를 한 번씩 방문하므로 일반적으로 **시간복잡도 O(N)**이다.

재귀 호출의 깊이는 트리 높이 `H`의 영향을 받는다.

- 균형 잡힌 트리 → H가 대략 `log N`
- 한쪽으로 치우친 트리 → H가 최대 `N`

---

# 4. 모스 코드 결정 트리

교재에서는 트리의 응용 사례로 **모스 코드 결정 트리**를 다룬다.

모스 코드(Morse Code)는 문자를 점(`.`)과 선(`-`)의 조합으로 표현한다.

## 인코딩(Encoding)

문자를 모스 코드로 바꾸는 과정을 **인코딩(encoding)**이라고 한다.

예를 들어

**SOS → `... --- ...`**

처럼 변환한다.

교재에서는 `(문자, 모스 코드)` 형태의 튜플을 리스트에 저장하고, 알파벳 순서에 맞춰 인덱스를 계산하여 해당 문자의 모스 코드를 바로 찾는다.

---

## 디코딩(Decoding)

반대로 모스 코드를 문자로 바꾸는 것을 **디코딩(decoding)**이라고 한다.

단순한 방법은 모스 코드 표를 처음부터 조사하면서 입력 코드와 같은 값을 찾는 것이다.

문자 수가 N개라면 최악의 경우 N개의 항목을 모두 검사해야 한다.

따라서 교재에서는 이를 더 효율적으로 처리하기 위해 **결정 트리(decision tree)**를 사용한다.

---

## 결정 트리를 이용한 디코딩

결정 트리에서는 루트부터 시작하여

- `.` → 왼쪽 자식
- `-` → 오른쪽 자식

으로 이동한다.

예를 들어 어떤 모스 코드가

`.--.`

라면

**왼쪽 → 오른쪽 → 오른쪽 → 왼쪽**

으로 이동한다.

모든 부호를 처리했을 때 도착한 노드에 저장된 문자가 디코딩 결과가 된다.

반대로 이동해야 하는 방향에 노드가 없다면 **잘못된 모스 코드**라는 것을 알 수 있다.

![모스 코드 결정 트리](/assets/img/posts/tree-chapter4/morse-decision-tree.png)
{: .study-diagram }

---

## 모스 코드 결정 트리 만들기

교재에서는 모스 코드 표에 있는 문자들을 하나씩 트리에 추가한다.

각 문자에 대해

1. 루트에서 시작한다.
2. 모스 코드의 각 부호를 확인한다.
3. `.`이면 왼쪽으로 이동한다.
4. `-`이면 오른쪽으로 이동한다.
5. 이동할 노드가 없다면 새 노드를 만든다.
6. 코드의 마지막 위치에 도착하면 해당 노드에 문자를 저장한다.

즉 하나의 문자열로 표현된 **결정 과정을 트리의 경로로 바꾸는 것**이다.

---

## 결정 트리의 의미

단순 탐색에서는 원하는 코드를 찾기 위해 표의 여러 항목을 확인해야 한다.

결정 트리에서는 입력되는 부호에 따라 필요한 방향으로만 이동한다.

교재에서는 결정 트리가 N개의 노드를 갖는 포화 이진 트리라면 높이가 `log₂N`이므로 디코딩에 필요한 탐색 역시 `log N`에 비례한다고 설명한다.

예를 들어 노드가 1,024개라면

- 단순 탐색 → 최악의 경우 1,024번 검사
- 결정 트리 → 약 10단계

로 탐색할 수 있다.

💡 **코테 포인트**

모스 코드 자체보다 **“조건 하나에 따라 왼쪽/오른쪽으로 이동하며 답을 좁혀간다”**는 결정 트리의 아이디어를 이해하는 것이 중요하다.

---

# 5. 수식 트리

### 수식 트리(Expression Tree)

**수식 트리(expression tree)**는 산술식을 이진 트리 형태로 표현한 것이다.

교재에서는

- **연산자(operator)** → 비단말 노드
- **피연산자(operand)** → 단말 노드

에 저장한다.

예를 들어

**(1 + 3) × (4 / 2)**

는 개념적으로 다음과 같이 표현할 수 있다.

```
          *
        /   \
       +     /
      / \   / \
     1   3 4   2
```

`*`의 왼쪽 자식인 `+`는 `1 + 3`이라는 하나의 수식을 나타내고, 오른쪽 자식인 `/`는 `4 / 2`라는 수식을 나타낸다.

![수식 트리 구조](/assets/img/posts/tree-chapter4/expression-tree.png)
{: .study-diagram }

---

## 수식 트리의 계산

수식 트리를 계산하려면 **자식 노드의 계산이 부모보다 먼저 끝나야 한다.**

위 예시에서 `*`를 계산하려면 먼저

- `1 + 3`
- `4 / 2`

를 계산해야 한다.

따라서 수식 트리 계산에는

> **왼쪽 → 오른쪽 → 루트**
> 

순서인 **후위순회(postorder)**가 적합하다.

```python
def evaluate(node):
    if node is None:
        return 0
    elif node.isLeaf():
        return node.data
    else:
        op1 = evaluate(node.left)
        op2 = evaluate(node.right)

        if node.data == '+':
            return op1 + op2
        elif node.data == '-':
            return op1 - op2
        elif node.data == '*':
            return op1 * op2
        elif node.data == '/':
            return op1 / op2
```

핵심은 현재 연산자를 계산하기 전에

`evaluate(left)`와 `evaluate(right)`

를 먼저 호출한다는 것이다.

---

## 수식의 표현 방법

수식은 **연산자와 피연산자의 상대적인 위치**에 따라 세 가지 방법으로 표현할 수 있다.

| 방식 | 구조 | A+B | 예시 |
| --- | --- | --- | --- |
| 전위(prefix) | 연산자 → 피연산자1 → 피연산자2 | `+ A B` | `+ 5 * A B` |
| 중위(infix) | 피연산자1 → 연산자 → 피연산자2 | `A + B` | `5 + A * B` |
| 후위(postfix) | 피연산자1 → 피연산자2 → 연산자 | `A B +` | `5 A B * +` |

이 구조는 이진 트리 순회와도 연결된다.

| 트리 순회 | 수식 표현 |
| --- | --- |
| 전위순회 | 전위표기(prefix) |
| 중위순회 | 중위표기(infix) |
| 후위순회 | 후위표기(postfix) |

---

### 후위표기법의 장점

사람에게는 중위표기법이 익숙하지만 컴퓨터가 처리하기에는 불편하다.

예를 들어

**A + B × C**

에서는 `×`의 우선순위가 `+`보다 높다는 것을 별도로 고려해야 한다.

반면 후위표기에서는 계산 순서 자체가 표현에 포함되어 있다.

교재에서 설명하는 후위표기법의 장점은 다음과 같다.

- 괄호 없이도 계산 순서를 알 수 있다.
- 연산자의 우선순위를 별도로 고려할 필요가 없다.
- 수식을 읽으면서 계산할 수 있다.

따라서 계산기 프로그램에서는 보통

**중위표기 입력 → 후위표기로 변환 → 후위표기 계산**

과정을 사용하며, 이 과정에서 **스택(stack)**이 사용된다.

💡 **코테 포인트**

1장에서 배운 스택이 여기서 다시 연결된다.

수식 문제가 나오면

**스택 ↔ 후위표기 ↔ 수식 트리**

의 관계를 같이 기억하는 것이 좋다.

---

## 전위표기식으로 수식 트리 만들기

전위표기는 **앞에서 뒤로** 읽으며 트리를 만든다.

전위표기에서는 연산자가 피연산자보다 먼저 나오기 때문에 처음 등장하는 연산자가 상위 노드가 되고 이후의 값들이 자식으로 연결된다.

---

## 후위표기식으로 수식 트리 만들기

후위표기는 **뒤에서 앞으로** 읽으면서 처리한다.

여기서 매우 중요한 점은

> **후위표기를 뒤에서 읽으므로 오른쪽 자식을 먼저 만든다.**
> 

는 것이다.

교재의 핵심 구현은 다음과 같다.

```python
def buildETree(expr):
    if len(expr) == 0:
        return None

    token = expr.pop()

    if token in "+-*/":
        node = BTNode(token)
        node.right = buildETree(expr)
        node.left = buildETree(expr)
        return node
    else:
        return BTNode(float(token))
```

연산자를 만나면 현재 노드를 만든 뒤

1. 오른쪽 서브 트리 생성
2. 왼쪽 서브 트리 생성

순서로 재귀 호출한다.

피연산자를 만나면 더 이상 자식이 필요하지 않으므로 단말 노드를 만들어 반환한다.

# 코딩테스트에서 기억할 내용

> 이 부분은 **교재의 별도 절이 아니라, 위 교재 내용을 코딩테스트 관점에서 연결해 정리한 내용**이다.
> 

### 1. 트리를 보면 재귀 구조부터 생각하기

트리는

**현재 노드 + 왼쪽 서브 트리 + 오른쪽 서브 트리**

라는 동일한 구조가 계속 반복된다.

따라서 문제를 보면 다음 구조를 생각해볼 수 있다.

```python
def solve(node):
    if node is None:
        return ...

    left = solve(node.left)
    right = solve(node.right)
    return ...
```

특히

- 노드 개수
- 트리 높이
- 서브 트리 계산
- 수식 트리 계산

같은 문제에서 기본이 되는 패턴이다.

---

### 2. DFS와 BFS 구분

| 문제 형태 | 우선 생각할 방법 |
| --- | --- |
| 깊게 내려가며 탐색 | DFS |
| 전위·중위·후위순회 | DFS 계열 |
| 레벨 순서 탐색 | BFS |
| 최상위에서 가까운 노드부터 탐색 | BFS |
| 모든 서브 트리 결과를 합쳐야 함 | 재귀/DFS |

**DFS → 재귀 또는 스택**

**BFS → 큐**

라고 연결해서 기억하면 된다.

---

### 3. 전위·중위·후위를 무작정 암기하지 않기

**전위 VLR**

→ 부모를 먼저 처리

**중위 LVR**

→ 왼쪽과 오른쪽 사이에서 부모 처리

**후위 LRV**

→ 자식을 모두 처리한 후 부모 처리

특히

> **자식의 결과가 있어야 현재 노드를 계산할 수 있다 → 후위**
> 

라는 판단이 중요하다.

수식 트리 계산이 대표적인 예이다.

---

### 4. 배열로 표현된 트리도 주의하기

문제에서 트리를 꼭 `Node` 클래스로 주는 것은 아니다.

완전 이진 트리나 힙처럼 배열로 주어질 수도 있다.

Python의 0-based 배열에서는

- 부모 → `(i-1)//2`
- 왼쪽 → `2*i+1`
- 오른쪽 → `2*i+2`

를 기억해두면 좋다.

---

### 5. 트리 문제에서 자주 확인할 값

트리 문제를 읽으면 먼저 다음을 확인한다.

- 루트는 무엇인가?
- 각 노드의 자식은 무엇인가?
- 단말 노드는 어디인가?
- 트리의 높이는 얼마인가?
- 모든 노드를 방문해야 하는가?
- 부모와 자식 중 누가 먼저 처리되어야 하는가?
- 레벨별로 탐색해야 하는가?

이 질문에 답하면 사용할 알고리즘이 상당 부분 결정된다.

# Chapter 04 핵심 요약

**트리(Tree)**

→ 계층적인 관계를 표현하는 비선형 자료구조

→ 노드와 간선으로 구성

→ 루트에서 여러 서브 트리로 나뉨

→ 재귀적인 구조

**이진 트리(Binary Tree)**

→ 각 노드의 자식이 최대 2개

→ 왼쪽 자식과 오른쪽 자식을 구분

**포화 이진 트리**

→ 교재 기준 모든 레벨이 꽉 찬 트리

→ 높이 k일 때 노드 수 = **2ᵏ - 1**

**완전 이진 트리**

→ 마지막 레벨을 제외하고 모두 채워짐

→ 마지막 레벨은 왼쪽부터 채워짐

→ 힙에서 사용

**균형 이진 트리**

→ 모든 노드에서 좌우 서브 트리의 높이 차이 ≤ 1

**배열 표현**

→ 교재의 1-based 기준

→ 부모 `i//2`

→ 왼쪽 `2i`

→ 오른쪽 `2i+1`

**링크 표현**

`Node = data + left + right`

**전위순회**

**V → L → R**

→ 부모 먼저

**중위순회**

**L → V → R**

→ 부모를 중간에 처리

**후위순회**

**L → R → V**

→ 자식 먼저

**레벨 순회**

→ 위에서 아래, 왼쪽에서 오른쪽

→ **Queue 사용**

**노드 수**

`left + right + 1`

**트리 높이**

`max(left, right) + 1`

**결정 트리**

조건에 따라 왼쪽 또는 오른쪽으로 이동하면서 결과를 찾는 구조

**수식 트리**

→ 연산자 = 비단말 노드

→ 피연산자 = 단말 노드
