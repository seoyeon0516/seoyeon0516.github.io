## 1. 리스트란?

### 리스트(List)

**리스트(list), 또는 선형 리스트(linear list)**는 자료들이 차례대로 나열된 **선형 자료구조**이다.

리스트의 각 요소는 **순서 또는 위치(position)**를 가지며, 요소들 사이에 빈 위치 없이 순서대로 나열된다.

![리스트 요소의 위치](/assets/img/posts/list-chapter3/list-positions.png)
{: .study-diagram }

리스트의 가장 큰 특징은 **어떤 위치에서도 요소를 삽입하거나 삭제할 수 있다는 것**이다.

예를 들어, `[A, B]`에서 위치 1에 C를 삽입하면 B가 뒤로 밀려 `[A, C, B]`가 된다.

![리스트 중간 삽입](/assets/img/posts/list-chapter3/list-insertion.png)
{: .study-diagram }

반대로 위치 0의 A를 삭제하면 뒤의 요소들이 앞으로 이동하여 `[C, B]`가 된다.

![리스트 요소 삭제](/assets/img/posts/list-chapter3/array-list-deletion.png)
{: .study-diagram }




즉, **삽입·삭제에 따라 각 요소의 위치가 변경될 수 있다.**  

### 스택·큐와의 차이

스택, 큐, 덱도 자료를 일렬로 저장하는 선형 자료구조이다.

하지만 스택이나 큐는 자료에 접근할 수 있는 위치가 전단이나 후단 등으로 제한된다.

반면 리스트는 **특정 위치에 대한 접근 제한이 없기 때문에 더 자유롭게 사용할 수 있는 선형 자료구조**이다.

### 리스트와 집합(Set)의 차이

리스트와 집합은 비슷해 보이지만 중요한 차이가 있다.

| 리스트(List) | 집합(Set) |
| --- | --- |
| 원소에 순서가 있음 | 원소의 순서가 없음 |
| 같은 값이 중복될 수 있음 | 중복된 원소를 허용하지 않음 |
| 선형 자료구조 | 선형 자료구조가 아님 |

---

### 리스트의 연산

리스트의 주요 연산은 다음과 같다.

| 연산 | 설명 |
| --- | --- |
| `insert(pos, e)` | pos 위치에 새로운 요소 e 삽입 |
| `delete(pos)` | pos 위치의 요소를 꺼내 반환 |
| `getEntry(pos)` | pos 위치의 요소를 삭제하지 않고 반환 |
| `isEmpty()` | 리스트가 비어 있으면 True |
| `isFull()` | 리스트가 가득 차 있으면 True |
| `size()` | 리스트의 전체 요소 수 반환 |

이 중 가장 중요한 연산은 **삽입(insert)과 삭제(delete)**이다.

스택이나 큐와 달리 리스트에서는 **처리할 위치 `pos`가 함께 주어진다는 것**이 특징이다.

또한 필요에 따라 다음과 같은 연산을 추가할 수 있다.

- `append(e)` : 리스트 뒤에 새로운 요소 추가
- `pop()` : 리스트의 마지막 요소 삭제
- `find(e)` : 요소 e의 위치 탐색
- `replace(pos, e)` : pos번째 요소를 e로 변경
- `display()` : 리스트 출력

이러한 연산은 기본적인 리스트 연산을 조합하여 구현할 수도 있다.

# 2. 배열 구조와 연결된 구조

리스트를 구현하는 방법은 크게 **배열 구조(array structure)**와 **연결된 구조(linked structure)**로 나눌 수 있다.

### 배열 구조

배열 구조에서는 요소들을 **메모리의 연속된 공간**에 저장한다.

```
[35][97][41][56][28]
 0   1   2   3   4
```

요소들이 연속되어 있기 때문에 원하는 위치의 요소를 빠르게 참조할 수 있다.

### 연결된 구조

연결된 구조에서는 요소들을 메모리의 한곳에 연속해서 저장하지 않는다.

대신 각각의 요소가 **다른 요소를 가리키는 링크(link)**를 가지도록 한다.

![연결된 구조](/assets/img/posts/list-chapter3/linked-structure.png)
{: .study-diagram }

이처럼 메모리에 흩어진 요소를 링크를 통해 연결하여 관리하는 방식을 **연결된 구조(linked structure)**라고 한다.

그중 자료를 일렬로 연결한 구조를 **연결 리스트(linked list)**라고 한다.

연결 구조에서 하나의 상자를 **노드(node)**라고 하며, 노드에는 데이터뿐만 아니라 다른 노드를 가리키는 링크가 함께 저장된다.

---

### 리스트 요소에 대한 접근

배열 구조와 연결된 구조의 가장 큰 차이 중 하나는 **원하는 요소에 접근하는 방법**이다.

#### 배열 구조

배열은 모든 요소의 크기가 같고 연속된 메모리에 저장된다.

따라서

> 배열 시작 주소 + (요소 크기 × 원하는 위치)
> 

를 이용해 원하는 요소의 주소를 바로 계산할 수 있다.

즉, 원하는 위치가 멀리 떨어져 있더라도 계산 횟수 자체는 크게 달라지지 않는다.

#### 연결된 구조

연결 리스트에서는 시작 노드의 주소만 알고 있다.

따라서 k번째 요소를 찾으려면 시작 노드부터 링크를 따라 이동해야 한다.

![연결 리스트 요소 접근](/assets/img/posts/list-chapter3/linked-list-traversal.png)
{: .study-diagram }

30를 찾으려면 10 → 20 → 30 순서로 이동해야 한다.

따라서 **원하는 위치의 요소에 접근하는 것은 배열 구조가 더 유리하다.**

💡 **코테 포인트**

배열에서 인덱스로 접근하는 것은 **O(1)**, 연결 리스트에서 특정 위치까지 찾아가는 것은 **O(n)**으로 생각하면 된다.

---

### 리스트의 용량

#### 배열 구조

기본적인 배열은 **용량이 고정**되어 있다.

너무 큰 배열을 미리 할당하면 메모리가 낭비되고, 너무 작게 할당하면 금방 포화 상태가 되어 새로운 요소를 넣을 수 없다.

#### 연결된 구조

연결된 구조는 필요한 노드를 그때그때 새롭게 만들어 사용한다.

따라서 배열처럼 정해진 용량을 미리 확보할 필요가 없으며, 책에서는 이러한 특성 때문에 **포화 상태가 없다고 설명한다.**

---

### 리스트의 삽입

배열 구조에서 중간에 새로운 요소를 넣으려면 삽입 위치 이후의 요소들을 한 칸씩 뒤로 이동시켜야 한다.

예를 들어,

```
[10][20][30]
```

에서 30 앞에 40을 삽입한다면 뒤의 요소들을 이동시켜 공간을 확보해야 한다.

이때 **뒤쪽 요소부터 이동해야 기존 데이터를 덮어쓰지 않는다.**

반면 연결 리스트에서는 삽입할 위치의 바로 앞 노드를 알고 있다면 **링크만 수정하면 된다.**

![연결 리스트 노드 삽입](/assets/img/posts/list-chapter3/linked-list-insertion.png)
{: .study-diagram }

다른 노드들은 이동할 필요가 없다.

---

### 리스트의 삭제

배열에서 중간 요소를 삭제하면 빈 공간이 생기므로 뒤의 요소들을 앞으로 당겨야 한다.

```
[35][97][41][56]

97 삭제

[35][41][56]
```

반면 연결 리스트에서는 삭제할 노드 바로 앞 노드의 링크를 수정하면 된다.

![연결 리스트 노드 삭제](/assets/img/posts/list-chapter3/linked-list-deletion.png)
{: .study-diagram }

따라서 책에서는 **삽입·삭제할 위치 바로 앞의 노드를 알고 있다면 연결 구조가 훨씬 효율적**이라고 설명한다.

💡 **코테 포인트**

여기서 **“연결 리스트 삽입·삭제 = 무조건 O(1)”**이라고 외우면 안 된다.

앞 노드를 이미 알고 있다면 링크 수정 자체는 O(1)이지만, `pos`번째 위치를 먼저 찾아야 한다면 탐색에 O(n)이 필요하다.

# 3. 배열 구조의 리스트: 파이썬 리스트

Python의 `list`는 **자료구조 리스트를 배열 구조로 구현한 사례**이다.

즉, 단순한 배열이라기보다 리스트의 여러 연산을 사용할 수 있도록 클래스로 구현되어 있다.

### Python 리스트의 주요 메서드

| 메서드 | 기능 |
| --- | --- |
| `append(e)` | 뒤에 새로운 요소 e 추가 |
| `extend(lst)` | 다른 리스트의 요소들을 추가 |
| `count(e)` | 요소 e의 개수 반환 |
| `index(e)` | 요소 e가 처음 등장하는 위치 반환 |
| `insert(pos, e)` | pos 위치에 e 삽입 |
| `pop(pos)` | pos 위치의 요소를 꺼내 반환 |
| `pop()` | 마지막 요소를 꺼내 반환 |
| `remove(e)` | 요소 e 제거 |
| `reverse()` | 요소들의 순서를 뒤집음 |
| `sort()` | 요소들을 정렬 |

Python 리스트는 배열 구조로 구현되어 있기 때문에 **원소 접근은 효율적이지만 중간 삽입·삭제는 요소 이동이 필요하다.**

---

### 파이썬 리스트의 용량 확장

Python 리스트는 배열 구조를 사용하지만 **용량이 제한되지 않도록 내부적으로 구현**되어 있다.

현재 공간이 모두 사용된 상태에서 새로운 요소를 `append()`하면 다음과 같은 과정으로 용량을 늘린다.

1. 기존 리스트보다 용량이 큰 새로운 공간을 할당한다.
2. 기존 리스트의 모든 요소를 새로운 공간으로 복사한다.
3. 새로운 요소를 삽입한다.
4. 기존 리스트 대신 새로운 리스트를 사용한다.

따라서 `append()`가 항상 똑같은 시간이 걸리는 것은 아니다.

공간이 남아 있다면 다음 공간에 바로 삽입할 수 있지만, 용량이 부족하면 새로운 공간을 만들고 기존 요소들을 복사하는 과정이 추가된다.

다만 책에서는 이러한 **용량 확장이 가끔 발생하고 내부적으로 처리되기 때문에 사용자가 직접 신경 쓸 필요는 없다**고 설명한다.

💡 **코테 포인트**

Python 코테에서는 배열 기반 리스트가 필요하다면 대부분 직접 구현하지 않고 `list`를 사용하면 된다.

특히 `append()`, `pop()`, 인덱싱은 매우 자주 사용한다.

# 4. 연결 리스트의 구조와 종류

## 연결 리스트의 구조

### 노드(Node)

연결 리스트의 각 요소는 **노드(node)**라는 단위로 구성된다.

하나의 노드는

- 데이터(data)
- 하나 이상의 링크(link)

를 가진다.

![노드의 데이터와 링크](/assets/img/posts/list-chapter3/node-structure.png)
{: .study-diagram }

`data`는 실제 저장할 자료이고, `link`는 다른 노드를 가리킨다.

배열과 달리 링크를 저장하기 위한 추가 공간이 필요하다.

---

### 헤드 포인터(Head Pointer)

연결 리스트에서는 시작 노드만 알고 있으면 링크를 따라가며 나머지 노드에 접근할 수 있다.

첫 번째 노드를 **머리 노드(head node)**라고 하고, 머리 노드의 주소를 저장하는 변수를 **헤드 포인터(head pointer)**라고 한다.

![연결 리스트의 헤드 포인터와 꼬리 노드](/assets/img/posts/list-chapter3/head-pointer.png)
{: .study-diagram }

마지막 노드는 **꼬리 노드(tail node)**라고 한다.

연결 리스트에서 `head`는 전체 리스트에 접근하기 위한 출발점이므로 매우 중요한 정보이다.

---

### 파이썬에서의 포인터

C/C++에서는 일반 변수와 주소를 저장하는 포인터를 구분한다.

하지만 Python에서는 변수가 객체 자체를 담는다기보다 **객체를 참조(reference)하는 방식**으로 사용된다.

또한 메모리 할당·해제와 같은 작업이 자동으로 처리되므로 연결 리스트를 구현할 때도 일반적인 Python 변수처럼 사용하면 된다.

---

## 연결 리스트의 종류

책에서는 연결 리스트를 **단순 연결 리스트, 원형 연결 리스트, 이중 연결 리스트**로 구분한다.     ch 3

### ① 단순 연결 리스트(Singly Linked List)

노드가 **다음 노드를 가리키는 하나의 링크**를 가진다.

꼬리 노드의 링크는 마지막임을 나타내기 위해 `None`을 가진다.

---

### ② 원형 연결 리스트(Circular Linked List)

꼬리 노드가 `None`을 가리키는 대신 **다시 머리 노드를 가리키도록 만든 구조**이다.

![원형 연결 리스트](/assets/img/posts/list-chapter3/circular-linked-list.png)
{: .study-diagram }

어떤 노드에서 시작하더라도 모든 노드에 접근할 수 있다는 특징이 있다.

하지만 `None`이 나오지 않으므로 **순회할 때 종료 조건을 주의해서 처리해야 한다.**

---

### ③ 이중 연결 리스트(Doubly Linked List)

각 노드가 두 개의 링크를 가진다.

- 이전 노드(previous node)
- 다음 노드(next node)

![이중 연결 리스트](/assets/img/posts/list-chapter3/doubly-linked-list.png)
{: .study-diagram }

따라서 앞쪽과 뒤쪽으로 모두 이동할 수 있다.

---

# 5. 단순 연결 구조로 리스트 구현하기

## Node 클래스

단순 연결 리스트의 노드는 **데이터와 다음 노드에 대한 링크**를 가진다.

책의 구현을 정리하면 기본 구조는 다음과 같다.

```python
class Node:
	def __init__(self, elem, link=None):
	self.data = elem
	self.link = link
```

예를 들어

```python
n1 = Node('A')
n2 = Node('B')
n1.link = n2
```

라면 `A → B`의 연결 구조가 만들어진다.

---

## Node의 append(node)

현재 노드 `self` 바로 뒤에 새로운 `node`를 삽입하는 연산이다.

기존에 `A → B`가 있을 때 X를 A 뒤에 삽입하려면 `A → X → B`가 되어야 한다.

따라서

1. X가 기존의 B를 가리키게 하고
2. A가 X를 가리키게 한다.

즉 핵심은

`node.link = self.link`

`self.link = node`

이다.

**기존 연결을 먼저 새로운 노드에 넘겨주고 현재 노드의 링크를 변경한다**는 순서가 중요하다.

---

## Node의 popNext()

현재 노드의 **바로 다음 노드를 연결 구조에서 꺼내는 연산**이다.

```
A → B → C
```

A에서 `popNext()`를 하면 B를 꺼내고,

```
A ───→ C
```

가 되도록 A의 링크를 C로 변경한다.

즉 연결 리스트의 삽입·삭제는 결국 **노드 자체를 이동시키는 것이 아니라 링크를 변경하는 것**이다.

---

## LinkedList 클래스

전체 연결 리스트에서는 **머리 노드를 가리키는 `head`**가 필요하다.

```python
class LinkedList:    
	def __init__(self):        
		self.head = None
```

공백 상태에서는 머리 노드가 없으므로 `head = None`이다.

---

### isEmpty()

`head`가 `None`이라면 연결된 노드가 하나도 없다는 뜻이다.

따라서

`self.head == None`

인지 검사하면 리스트의 공백 상태를 확인할 수 있다.

### isFull()

연결 리스트는 배열처럼 미리 정해진 용량을 사용하는 것이 아니므로 책의 구현에서는 항상 `False`를 반환하도록 처리한다.

---

## getNode(pos)

연결 리스트에서 `pos`번째 요소를 얻기 위해서는 먼저 **pos번째 노드 자체를 찾아야 한다.**

배열에서는 `A[pos]`로 바로 접근할 수 있지만 연결 리스트에서는 불가능하다.

![링크를 따라 pos 위치의 노드 탐색](/assets/img/posts/list-chapter3/get-node-traversal.png)
{: .study-diagram }

`getNode(2)`라면

`A → B → C`

순서로 링크를 따라 이동하여 C 노드를 반환한다.

`pos`가 유효하지 않으면 `None`을 반환한다.

---

## getEntry(pos)

`getNode(pos)`로 원하는 노드를 찾은 다음 그 노드의 `data`를 반환한다.

즉,

> `getNode(pos)` → 노드 자체 반환
> 
> 
> `getEntry(pos)` → 그 노드의 데이터 반환
> 

으로 구분하면 된다.

---

## insert(pos, e)

pos 위치에 새로운 요소를 삽입하려면 **pos-1 위치의 노드 `before`를 찾는 것**이 중요하다.

```
before       기존 pos
  ↓             ↓
 [B] ─────────→ [P]
```

새로운 X를 삽입하면

```
[B] → [X] → [P]
```

가 되어야 한다.

과정은 다음과 같다.

1. 새로운 노드 생성
2. `pos-1` 위치의 `before` 탐색
3. `before` 뒤에 새로운 노드 추가

단, **리스트의 맨 앞에 삽입하는 경우**에는 이전 노드가 없다.

이 경우 새로운 노드가 기존 `head`를 가리키게 하고, `head = 새로운 노드`로 변경해야 한다.

---

## delete(pos)

삭제도 삽입과 마찬가지로 **pos-1 위치의 노드 `before`**가 중요하다.

```
[B] → [X] → [P]
       ↑
      삭제
```

B가 X를 건너뛰고 P를 가리키게 만들면

```
[B] ─────→ [P]
```

가 된다.

따라서 일반적인 삭제는 `before.popNext()`를 이용한다.

단, **머리 노드를 삭제하는 경우에는 `head` 자체를 다음 노드로 변경**해야 한다.

---

## size()

연결 리스트에서는 기본적으로 몇 개의 노드가 연결되어 있는지 바로 알 수 없다.

따라서 `head`부터 시작해 `None`을 만날 때까지 이동하면서 노드의 수를 센다.

```
head
 ↓
[A] → [B] → [C] → None
 1      2      3
```

책에서는 추가로 `count`라는 멤버 변수를 두는 방법도 설명한다.

노드 수를 `count`에 계속 저장해두면 `size()`는 `count`만 반환하면 되므로 훨씬 간단해진다.

대신 삽입할 때 `count`를 증가시키고 삭제할 때 감소시키는 등 **모든 관련 연산에서 값의 일관성을 유지해야 한다.**

---

## display()

연결 리스트를 출력할 때도 `head`부터 시작해서 링크를 따라 마지막 노드까지 방문한다.

핵심적인 순회 구조는 다음과 같다.

```python
ptr = self.head

while ptr is not None:
	print(ptr.data, end='->')
	ptr = ptr.linkprint('None')
```

결과:

`10->20->30->None`

이러한 **`ptr = ptr.link` 형태의 순회가 연결 리스트 구현에서 가장 기본적인 패턴**이다.

책에서는 `getNode`, `getEntry`, `insert`, `delete`, `size`, `display` 등을 차례로 구현하면서 단순 연결 리스트를 완성한다.     ch 3

---

### 연결 리스트와 Python 리스트 비교

책에서는 동일한 삽입·교체·삭제 연산을 직접 만든 `LinkedList`와 Python `list`에 적용한다.

두 자료구조의 **내부 구현 방법은 서로 다르지만 결과적으로 같은 리스트 연산을 수행할 수 있다.**

즉,

```
Python list
[20, 30, 50, 10, 40]

LinkedList
20 → 30 → 50 → 10 → 40 → None
```

처럼 저장 구조는 다르지만 자료구조 리스트가 제공해야 하는 기능은 동일하다.

---

# 6. 이중 연결 구조로 리스트 구현하기

이중 연결 리스트에서는 단순 연결 리스트와 달리 **각 노드에 이전 노드와 다음 노드를 가리키는 두 개의 링크**가 필요하다.

따라서 노드 구조와 삽입·삭제 연산도 조금 더 복잡해진다.

## DNode 클래스

이중 연결 리스트의 노드는 다음 세 가지 정보를 가진다.

![이중 연결 리스트의 노드 구조](/assets/img/posts/list-chapter3/dnode-structure.png)
{: .study-diagram }

- `data` : 데이터
- `prev` : 이전 노드
- `next` : 다음 노드

책의 기본 구조는 다음과 같다.

```python
class DNode:
	def __init__(self, elem, prev=None, next=None):
		self.data = elem
		self.next = next
		self.prev = prev
```

머리 노드의 `prev`는 `None`, 꼬리 노드의 `next`는 `None`이 된다.

---

## DNode의 append(node)

이중 연결에서는 새로운 노드를 추가할 때 **next와 prev를 모두 올바르게 연결해야 한다.**

A와 B 사이에 X를 넣는다면

![이중 연결된 두 노드](/assets/img/posts/list-chapter3/doubly-linked-nodes.png)
{: .study-diagram }

![이중 연결 리스트 노드 삽입 전](/assets/img/posts/list-chapter3/dnode-insertion-before.png)
{: .study-diagram }

가 되어야 한다.

따라서 다음 관계가 모두 만들어져야 한다.

- X의 다음 → B
- X의 이전 → A
- B의 이전 → X
- A의 다음 → X

단순 연결 리스트보다 수정해야 하는 링크가 많다.

---

## DNode의 popNext()

삭제 역시 앞뒤 링크를 모두 수정해야 한다.

![이중 연결 리스트 노드 삽입 후](/assets/img/posts/list-chapter3/dnode-insertion-after.png)
{: .study-diagram }

따라서

- A의 `next` → B
- B의 `prev` → A

가 되도록 수정한다.

---

## DblLinkedList 클래스

이중 연결 리스트도 전체 리스트를 관리하기 위해 `head`를 사용한다.

`isEmpty()`, `isFull()`, `getEntry()` 등은 단순 연결 리스트와 거의 같은 방법으로 구현할 수 있다.

다만 단순 연결 리스트에서 사용한 `link` 대신 **`next`를 사용한다.**

---

## insert(pos, e)

일반적인 삽입은 단순 연결 리스트와 비슷하다.

하지만 머리에 새로운 노드를 삽입한다면

1. 새 노드의 `next` → 기존 head
2. 기존 head의 `prev` → 새 노드
3. head → 새 노드

처럼 양쪽 링크를 처리해야 한다.

---

## delete(pos)

삭제 역시 단순 연결 리스트와 유사하지만, 머리 노드를 삭제한다면 새로운 머리 노드의 `prev`도 반드시 `None`으로 만들어야 한다.

![이중 연결 리스트 노드 삭제](/assets/img/posts/list-chapter3/dnode-deletion.png)
{: .study-diagram }

책에서는 `DNode`의 `append()`와 `popNext()`를 먼저 수정한 뒤 이를 이용하여 `DblLinkedList`의 삽입·삭제를 구현한다.

# 코딩테스트에서 기억할 내용

> 이 부분은 **교재의 별도 절이 아니라, 위 교재 내용을 코테 관점에서 정리한 내용**이다.
> 

### 1. 배열 vs 연결 리스트

| 연산 | 배열 구조 | 연결 리스트 |
| --- | --- | --- |
| 인덱스 접근 | **O(1)** | O(n) |
| 특정 값 탐색 | O(n) | O(n) |
| 중간 삽입·삭제 | O(n) | 링크 변경 자체는 O(1) |
| pos 위치 탐색 | O(1) | O(n) |

특히 연결 리스트에서 삽입·삭제가 빠르다는 말에는 **“수정해야 할 노드의 위치를 이미 알고 있을 때”**라는 조건이 붙는다.

---

### 2. Python에서는 기본적으로 list 사용

코딩테스트에서 배열 기반 리스트가 필요하면 보통

`arr = []`

로 만들고,

- `arr[i]`
- `arr.append(x)`
- `arr.pop()`
- `len(arr)`

등을 사용한다.

---

### 3. 연결 리스트 문제의 핵심

연결 리스트 문제를 보면 **데이터 값보다 링크를 먼저 생각한다.**

삽입:

`A → B`

`A → X → B`

삭제:

`A → X → B`

`A ─────→ B`

즉,

> **“현재 노드가 다음에 누구를 가리켜야 하는가?”**
> 

를 그림으로 먼저 정리하면 코드가 훨씬 쉬워진다.

---

# Chapter 03 핵심 요약

**리스트(List)**

→ 자료가 순서대로 나열된 선형 자료구조

→ 원하는 위치에서 삽입·삭제 가능

**배열 구조**

→ 연속된 메모리 사용

→ 원하는 위치에 빠르게 접근

→ 중간 삽입·삭제 시 요소 이동 필요

**연결된 구조**

→ 메모리에 흩어진 노드를 링크로 연결

→ `Node = data + link`

→ 원하는 위치까지 링크를 따라 이동

→ 위치를 알고 있다면 링크 수정으로 삽입·삭제

**Python list**

→ 배열 구조로 구현된 리스트

→ 용량 부족 시 내부적으로 더 큰 공간 확보 후 기존 요소 복사

**단순 연결 리스트**

→ `data + link`

→ `head`에서 시작

→ `link`를 따라 한 방향으로 이동

**원형 연결 리스트**

→ 꼬리 노드가 다시 머리 노드를 가리킴

**이중 연결 리스트**

→ `prev + data + next`

→ 앞뒤 방향으로 연결
