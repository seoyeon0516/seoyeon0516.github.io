## 1. 정렬이란?

### 정렬(Sorting)

**정렬(Sorting)**은 순서 없이 나열된 데이터를 일정한 기준에 따라 순서대로 재배열하는 작업이다.

정렬은 단순히 숫자를 작은 순서대로 나열하는 것뿐만 아니라, 데이터의 특정 속성을 기준으로 순서를 결정하는 작업까지 포함한다.

예를 들어 쇼핑몰에서 상품을 가격순이나 평점순으로 정렬하거나, 학생들의 성적을 점수순으로 정렬하는 것이 대표적인 사례이다.

정렬은 데이터를 보기 쉽게 만드는 역할도 하지만, 데이터를 효율적으로 탐색하고 처리하기 위한 중요한 전처리 과정이기도 하다.

### 오름차순과 내림차순

| 구분 | 의미 | 예시 |
| --- | --- | --- |
| 오름차순(Ascending Order) | 작은 값부터 큰 값으로 정렬 | `[1, 2, 3, 4, 5]` |
| 내림차순(Descending Order) | 큰 값부터 작은 값으로 정렬 | `[5, 4, 3, 2, 1]` |
| 사전식 순서(Lexicographical Order) | 문자열을 사전의 단어 순서처럼 비교 | `['apple', 'banana', 'cat']` |

### 정렬 관련 용어

정렬의 대상이 되는 데이터를 **레코드(Record)**라고 하며, 레코드는 여러 개의 **필드(Field)**로 구성될 수 있다.

레코드의 필드 중에서 정렬의 기준이 되는 값을 **키(Key) 또는 정렬 키(Sort Key)**라고 한다.

예를 들어 상품 정보가 다음과 같다고 가정하자.

`상품 = (이름, 가격, 평점)`

- 레코드: 상품 하나에 대한 전체 정보
- 필드: 이름, 가격, 평점
- 키: 정렬 기준으로 선택한 가격 또는 평점

즉, 정렬은 레코드들을 특정 키의 순서에 따라 재배열하는 과정이다. 학생의 이름·점수·과목으로 이루어진 레코드에서는 점수를 정렬 키로 선택할 수도 있다.

![레코드의 필드와 점수를 정렬 키로 선택한 예](/assets/img/posts/sorting-chapter6/record-field-key.png)
{: .study-diagram }

### 정렬 알고리즘의 분류

정렬 알고리즘은 데이터를 어떤 방식으로 정렬하는지에 따라 구분할 수 있다.

| 구분 | 특징 | 대표 알고리즘 |
| --- | --- | --- |
| 비교 기반 정렬 | 두 데이터를 비교하여 순서 결정 | 선택 정렬, 삽입 정렬, 퀵 정렬 |
| 비비교 기반 정렬 | 데이터의 자릿수 등 특정 속성을 이용 | 기수 정렬 |

일반적으로 선택 정렬과 삽입 정렬은 구현이 단순하지만 입력이 커지면 비효율적이다. 반면 퀵 정렬과 같은 알고리즘은 상대적으로 복잡하지만 평균적으로 높은 성능을 보인다.

다만 모든 상황에서 가장 좋은 정렬 알고리즘은 존재하지 않는다. 입력 데이터의 크기와 상태, 메모리 사용량, 안정성 등을 고려하여 선택해야 한다.

### 정렬의 안정성(Stability)

**안정 정렬(Stable Sort)**은 정렬 기준인 키가 같은 데이터들의 상대적인 순서가 정렬 전후에 유지되는 정렬이다.

예를 들어 다음과 같은 데이터가 있다고 가정하자.

`[(철수, 90), (영희, 80), (민수, 90)]`

점수를 기준으로 내림차순 정렬한다면 안정 정렬의 결과는 다음과 같다.

`[(철수, 90), (민수, 90), (영희, 80)]`

철수와 민수는 점수가 90점으로 같으므로 원래의 상대적인 순서인 철수 → 민수가 유지되어야 한다.

![점수가 같은 철수와 민수의 순서가 유지되는 안정 정렬](/assets/img/posts/sorting-chapter6/stable-sort.png)
{: .study-diagram }

안정성이 중요한 이유는 여러 기준을 이용해 데이터를 정렬할 때 기존 순서를 보존할 수 있기 때문이다.

| 정렬 알고리즘 | 안정성 |
| --- | --- |
| 선택 정렬 | 불안정 |
| 삽입 정렬 | 안정 |
| 퀵 정렬 | 불안정 |
| 기수 정렬 | 안정(안정적인 버킷 처리 방식) |
| 파이썬 `sort()`, `sorted()` | 안정 |

💡 코테 포인트

여러 조건으로 정렬해야 할 때 안정성이 중요할 수 있다. 예를 들어 이름순으로 정렬한 데이터를 다시 점수순으로 안정 정렬하면, 점수가 같은 학생들의 이름순이 유지된다.

### 제자리 정렬(In-place Sorting)

**제자리 정렬(In-place Sorting)**은 입력 배열 이외에 별도의 추가 배열을 사용하지 않고 데이터를 정렬하는 방법이다.

예를 들어 선택 정렬은 입력 리스트 안에서 원소의 위치를 교환하여 정렬하므로 제자리 정렬에 해당한다.

| 정렬 알고리즘 | 제자리 정렬 여부 |
| --- | --- |
| 선택 정렬 | O |
| 삽입 정렬 | O |
| 퀵 정렬 | O(배열 내 분할, 단 재귀 호출 스택 사용) |
| 기수 정렬 | X(버킷을 위한 추가 메모리 사용) |

제자리 정렬이라고 해서 추가 메모리가 완전히 0이라는 의미는 아니다. 퀵 정렬처럼 배열을 별도로 만들지 않더라도 재귀 호출을 위한 스택 메모리가 필요할 수 있다.

### 내부 정렬과 외부 정렬

- 내부 정렬(Internal Sorting): 모든 데이터를 메인 메모리에 올려 정렬하는 방법
- 외부 정렬(External Sorting): 데이터가 대부분 외부 저장장치에 있고 일부만 메모리에 올려 정렬하는 방법

외부 정렬은 메모리에 한 번에 올릴 수 없는 대용량 데이터를 처리할 때 사용한다.

## 2. 선택 정렬(Selection Sort)

### 선택 정렬이란?

**선택 정렬(Selection Sort)**은 정렬되지 않은 부분에서 가장 작은 값을 찾아 현재 위치의 값과 교환하는 과정을 반복하는 알고리즘이다.

핵심 원리는 최솟값을 선택하여 앞쪽부터 하나씩 확정하는 것이다.

정렬이 진행될수록 리스트는 두 부분으로 나뉜다.

- 정렬된 부분: 앞쪽에 위치하며 더 이상 변경할 필요가 없는 영역
- 정렬되지 않은 부분: 최솟값을 계속 찾아야 하는 영역

### 선택 정렬의 동작 과정

입력 리스트가 `[6, 3, 7, 4, 1]`이라고 가정하자.

| 단계 | 동작 | 결과 |
| --- | --- | --- |
| 초기 | 정렬되지 않은 상태 | `[6, 3, 7, 4, 1]` |
| 1 | 최솟값 1을 찾아 6과 교환 | `[1, 3, 7, 4, 6]` |
| 2 | 나머지 중 최솟값 3 선택 | `[1, 3, 7, 4, 6]` |
| 3 | 나머지 중 최솟값 4를 7과 교환 | `[1, 3, 4, 7, 6]` |
| 4 | 나머지 중 최솟값 6을 7과 교환 | `[1, 3, 4, 6, 7]` |

원소가 n개라면 이러한 선택 과정을 n-1번 반복하면 정렬이 완료된다.

첫 단계에서는 전체에서 가장 작은 1을 찾아 맨 앞의 6과 교환한다. 교환이 끝나면 1의 자리는 확정되고, 다음 단계에서는 1을 제외한 구간에서 최솟값을 찾는다.

![선택 정렬 첫 단계에서 최솟값 1과 맨 앞의 6을 교환](/assets/img/posts/sorting-chapter6/selection-first-swap-detail.png)
{: .study-diagram }

![최솟값을 선택해 앞쪽으로 교환하는 선택 정렬 과정](/assets/img/posts/sorting-chapter6/selection-sort-steps.png)
{: .study-diagram }

### 선택 정렬 구현

```python
def selection_sort(A):
    n = len(A)

    for i in range(n - 1):
        least = i
        for j in range(i + 1, n):
            if A[j] < A[least]:
                least = j
        A[i], A[least] = A[least], A[i]

    return A
```

코드의 핵심

- `i`: 정렬되지 않은 부분의 시작 인덱스
- `least`: 현재까지 발견한 최솟값의 인덱스
- `j`: 나머지 원소를 탐색하는 인덱스
- `A[i], A[least] = A[least], A[i]`: 두 원소의 위치 교환

파이썬에서는 임시 변수 없이 두 값을 교환할 수 있다.

`a, b = b, a`

### 선택 정렬의 시간 복잡도

선택 정렬에서는 최솟값을 찾기 위해 정렬되지 않은 부분을 끝까지 탐색해야 한다.

첫 번째 단계에서는 n-1개, 두 번째 단계에서는 n-2개, 마지막 단계에서는 1개를 비교한다.

따라서 전체 비교 횟수는 다음과 같다.

$$
T(n)=(n-1)+(n-2)+\cdots+1
$$

$$
T(n)=\frac{n(n-1)}{2}
$$

최고차항은 n²이므로 시간 복잡도는 **O(n²)**이다.

| 경우 | 시간 복잡도 |
| --- | --- |
| 최선 | O(n²) |
| 평균 | O(n²) |
| 최악 | O(n²) |

선택 정렬은 입력 데이터가 이미 정렬되어 있어도 모든 원소를 비교한다. 따라서 입력 데이터의 구성과 관계없이 비교 횟수가 일정하다.

### 선택 정렬의 특징

- 구현이 간단하고 이해하기 쉽다.
- 추가 배열을 사용하지 않는 제자리 정렬이다.
- 일반적으로 안정성을 만족하지 않는다.
- 입력 데이터의 상태와 관계없이 O(n²)의 시간이 필요하다.
- 데이터의 크기가 작을 때 사용할 수 있다.
- 비교 횟수는 많지만 교환 횟수는 최대 n-1번이다.

💡 코테 포인트

선택 정렬에서 가장 중요한 것은 최솟값 자체가 아니라 최솟값의 인덱스를 기억한다는 것이다.

최솟값을 발견할 때마다 바로 교환하는 것이 아니라, 내부 반복문이 끝난 뒤 최솟값의 위치와 현재 위치를 한 번 교환한다.

## 3. 삽입 정렬(Insertion Sort)

### 삽입 정렬이란?

**삽입 정렬(Insertion Sort)**은 정렬되지 않은 원소를 하나씩 선택하여 이미 정렬된 부분의 적절한 위치에 삽입하는 알고리즘이다.

손에 들고 있는 카드를 정렬하는 방식과 비슷하다.

새로운 카드를 받을 때마다 기존에 정렬된 카드들 사이에서 알맞은 위치를 찾아 끼워 넣는 것이다.

핵심 원리는 정렬된 부분을 유지하면서 새로운 원소를 적절한 위치에 삽입하는 것이다.

### 삽입 정렬의 동작 과정

입력 리스트가 `[6, 3, 7, 4, 1]`이라고 가정하자.

처음에는 첫 번째 원소 6이 정렬된 상태라고 가정한다.

| 단계 | 삽입할 값 | 결과 |
| --- | --- | --- |
| 초기 | - | `[6, 3, 7, 4, 1]` |
| 1 | 3 | `[3, 6, 7, 4, 1]` |
| 2 | 7 | `[3, 6, 7, 4, 1]` |
| 3 | 4 | `[3, 4, 6, 7, 1]` |
| 4 | 1 | `[1, 3, 4, 6, 7]` |

삽입할 값을 `key`라고 하면, 정렬된 부분을 오른쪽부터 확인하면서 `key`보다 큰 값을 한 칸씩 뒤로 이동시킨다.

`key`보다 작거나 같은 값을 만나면 이동을 멈추고 빈자리에 `key`를 삽입한다.

![원소를 하나씩 정렬된 부분에 삽입하는 과정](/assets/img/posts/sorting-chapter6/insertion-sort-steps.png)
{: .study-diagram }

### 삽입 정렬 구현

```python
def insertion_sort(A):
    n = len(A)

    for i in range(1, n):
        key = A[i]
        j = i - 1

        while j >= 0 and A[j] > key:
            A[j + 1] = A[j]
            j -= 1

        A[j + 1] = key

    return A
```

코드의 핵심

- `i`: 새롭게 삽입할 원소의 인덱스
- `key`: 정렬된 부분에 삽입할 값
- `j`: 정렬된 부분을 오른쪽부터 탐색하는 인덱스
- `A[j + 1] = A[j]`: `key`보다 큰 값을 오른쪽으로 이동
- `A[j + 1] = key`: 올바른 위치에 삽입

### 왜 오른쪽부터 비교할까?

삽입 정렬에서는 새로운 원소를 넣을 자리를 확보해야 한다.

정렬된 부분의 오른쪽부터 탐색하면 `key`보다 큰 원소를 발견하는 즉시 오른쪽으로 이동시킬 수 있다.

예를 들어 `[3, 6, 7, 4]`에서 4를 삽입한다면 다음과 같다.

1. 7이 4보다 크므로 오른쪽으로 이동
2. 6이 4보다 크므로 오른쪽으로 이동
3. 3은 4보다 작으므로 탐색 종료
4. 3과 6 사이에 4 삽입

결과는 `[3, 4, 6, 7]`이 된다.

![4를 따로 보관하고 큰 값을 오른쪽으로 이동한 뒤 빈자리에 삽입하는 과정](/assets/img/posts/sorting-chapter6/insertion-shift-detail.png)
{: .study-diagram }

### 삽입 정렬의 시간 복잡도

삽입 정렬은 입력 데이터의 상태에 따라 연산 횟수가 달라진다.

최선의 경우

이미 오름차순으로 정렬된 리스트라면 원소를 이동시킬 필요가 없다.

각 원소를 한 번씩 비교하므로

O(n)

이다.

최악의 경우

내림차순으로 정렬된 리스트를 오름차순으로 정렬하는 경우이다.

새로운 원소를 삽입할 때마다 앞쪽의 모든 원소를 이동시켜야 한다.

$$
T(n)=1+2+3+\cdots+(n-1)
$$

$$
T(n)=\frac{n(n-1)}{2}=O(n^2)
$$

| 경우 | 시간 복잡도 |
| --- | --- |
| 최선 | O(n) |
| 평균 | O(n²) |
| 최악 | O(n²) |

### 삽입 정렬의 특징

- 제자리 정렬이다.
- 안정성을 만족한다.
- 입력 데이터의 구성에 따라 실행 시간이 달라진다.
- 이미 정렬된 데이터에 대해서는 매우 효율적이다.
- 원소를 삽입하기 위해 많은 데이터 이동이 발생할 수 있다.
- 거의 정렬된 데이터를 처리하는 경우 유용하다.

삽입 정렬이 안정적인 이유는 `A[j] > key`인 경우에만 이동시키기 때문이다. 두 값이 같다면 이동시키지 않으므로 동일한 키를 가진 데이터들의 상대적인 순서가 유지된다.

💡 코테 포인트

선택 정렬과 삽입 정렬은 모두 평균 O(n²)이지만 처리 방식이 다르다.

- 선택 정렬: 최솟값을 찾아 교환
- 삽입 정렬: 현재 값을 올바른 위치에 삽입

특히 삽입 정렬은 **이미 정렬된 데이터에서 O(n)**이 가능하다는 점이 중요한 차이이다.

## 4. 퀵 정렬(Quick Sort)

### 퀵 정렬이란?

**퀵 정렬(Quick Sort)**은 하나의 기준값을 선택하고, 그 값을 중심으로 리스트를 두 부분으로 나누어 정렬하는 알고리즘이다.

기준이 되는 값을 **피벗(Pivot)**이라고 한다.

피벗보다 작은 값은 왼쪽으로, 큰 값은 오른쪽으로 이동시킨 뒤 각각의 부분 리스트에 같은 과정을 반복한다.

퀵 정렬은 분할 정복(Divide and Conquer) 전략을 사용한다.

### 분할 정복(Divide and Conquer)

큰 문제를 여러 개의 작은 문제로 나누어 해결한 뒤, 그 결과를 이용해 전체 문제를 해결하는 전략이다.

퀵 정렬에서는 다음 과정을 반복한다.

1. 분할(Divide): 피벗을 기준으로 작은 값과 큰 값을 나눈다.
2. 정복(Conquer): 나뉜 부분 리스트를 각각 재귀적으로 정렬한다.
3. 결합(Combine): 분할이 끝난 배열 자체가 정렬된 결과가 된다.

퀵 정렬은 별도의 병합 과정이 필요하지 않다는 특징이 있다.

### 퀵 정렬의 동작 과정

입력 리스트가 `[5, 3, 8, 4, 9, 1, 6, 2, 7]`이라고 가정하자.

첫 번째 원소 5를 피벗으로 선택한다.

1단계: 피벗 선택

`pivot = 5`

2단계: 피벗을 기준으로 분할

5보다 작은 값: `[3, 4, 1, 2]`

피벗: `[5]`

5보다 큰 값: `[8, 9, 6, 7]`

3단계: 부분 리스트에 같은 과정 반복

왼쪽 부분: `[1, 2, 3, 4]`

오른쪽 부분: `[6, 7, 8, 9]`

최종 결과

`[1, 2, 3, 4, 5, 6, 7, 8, 9]`

여기서 중요한 점은 분할 직후의 왼쪽과 오른쪽 부분 리스트 내부까지 정렬되어 있을 필요는 없다는 것이다.

피벗을 기준으로 값들이 올바른 방향에 배치되기만 하면 된다.

![피벗 5를 기준으로 작은 값과 큰 값을 나누는 퀵 정렬](/assets/img/posts/sorting-chapter6/quick-sort-partition.png)
{: .study-diagram }

### 퀵 정렬 구현

```python
def partition(A, left, right):
    pivot = A[left]
    low = left + 1
    high = right

    while low <= high:
        while low <= high and A[low] <= pivot:
            low += 1
        while low <= high and A[high] > pivot:
            high -= 1

        if low < high:
            A[low], A[high] = A[high], A[low]

    A[left], A[high] = A[high], A[left]
    return high

def quick_sort(A, left, right):
    if left < right:
        q = partition(A, left, right)
        quick_sort(A, left, q - 1)
        quick_sort(A, q + 1, right)
```

사용 방법은 다음과 같다.

`quick_sort(data, 0, len(data) - 1)`

### partition() 함수의 역할

**partition()**은 피벗을 기준으로 리스트를 두 부분으로 나누고, 최종적으로 피벗이 위치한 인덱스를 반환하는 함수이다.

주요 변수는 다음과 같다.

| 변수 | 역할 |
| --- | --- |
| `pivot` | 분할 기준값 |
| `left` | 정렬할 부분 리스트의 시작 인덱스 |
| `right` | 정렬할 부분 리스트의 마지막 인덱스 |
| `low` | 왼쪽에서 오른쪽으로 탐색하는 인덱스 |
| `high` | 오른쪽에서 왼쪽으로 탐색하는 인덱스 |
| `q` | 분할 완료 후 피벗의 위치 |

분할 과정에서는 `low`와 `high`를 이동시키면서 피벗을 기준으로 잘못 배치된 원소를 찾는다.

- `low`: 피벗보다 큰 원소를 발견할 때까지 오른쪽으로 이동
- `high`: 피벗 이하의 원소를 발견할 때까지 왼쪽으로 이동
- `low < high`: 두 원소를 교환
- 두 인덱스가 교차하면 피벗을 최종 위치로 이동

마지막으로 피벗의 인덱스를 반환한다.

![퀵 정렬에서 low와 high가 찾은 8과 2를 교환하는 예](/assets/img/posts/sorting-chapter6/quick-low-high-swap.png)
{: .study-diagram }

### 퀵 정렬의 재귀 호출

퀵 정렬은 분할된 부분 리스트를 다시 퀵 정렬 함수에 전달한다.

`quick_sort(A, left, q - 1)`은 피벗의 왼쪽 부분을 정렬한다.

`quick_sort(A, q + 1, right)`은 피벗의 오른쪽 부분을 정렬한다.

부분 리스트의 크기가 1 이하가 되면 이미 정렬된 상태이므로 재귀 호출을 종료한다.

재귀 종료 조건: `left >= right`

### 퀵 정렬의 시간 복잡도

퀵 정렬의 성능은 피벗을 기준으로 얼마나 균등하게 분할되는지에 따라 달라진다.

최선의 경우

피벗이 리스트를 거의 절반씩 나누는 경우이다.

분할할 때마다 문제의 크기가 절반으로 감소한다.

`n → n/2 → n/4 → n/8 → ...`

분할 깊이는 약 log₂n이고, 각 깊이에서 전체적으로 O(n)의 작업이 수행된다.

따라서 **O(n log n)** 이다.

**최악의 경우**

피벗이 항상 최솟값 또는 최댓값으로 선택되어 한쪽 부분 리스트만 남는 경우이다.

`n → n-1 → n-2 → ... → 1`

첫 번째 원소를 피벗으로 사용하는 구현에서는 이미 정렬된 리스트가 대표적인 최악의 입력이 될 수 있다.

따라서 **O(n²)** 이다.

균등하게 나뉘면 재귀 호출의 깊이가 빠르게 줄어든다. 한쪽에만 원소가 남으면 거의 같은 크기의 문제를 계속 풀어야 한다.

![퀵 정렬에서 균등 분할과 불균등 분할의 재귀 구조 비교](/assets/img/posts/sorting-chapter6/quick-partition-balance.png)
{: .study-diagram }

| 경우 | 시간 복잡도 |
| --- | --- |
| 최선 | O(n log n) |
| 평균 | O(n log n) |
| 최악 | O(n²) |

### 퀵 정렬의 특징

- 평균적으로 매우 빠른 정렬 알고리즘이다.
- 분할 정복 전략을 사용한다.
- 일반적으로 안정성을 만족하지 않는다.
- 배열 내부에서 원소를 교환하는 제자리 정렬 방식이다.
- 피벗 선택에 따라 성능이 달라진다.
- 불균형한 분할이 반복되면 O(n²)이 발생한다.

### 피벗 선택 방법

퀵 정렬의 성능을 개선하려면 가능한 한 균등한 분할이 이루어지도록 피벗을 선택해야 한다.

대표적인 방법으로 **Median of Three**가 있다.

리스트의 첫 번째, 가운데, 마지막 원소 세 개 중에서 중간값을 피벗으로 선택하는 방식이다.

이는 특정 입력에서 극단적으로 불균형한 분할이 발생할 가능성을 줄이기 위한 방법이다. 다만 최악의 시간 복잡도 O(n²)을 완전히 제거하는 것은 아니다.

💡 코테 포인트

퀵 정렬에서 가장 중요한 것은 세 가지이다.

1. 피벗을 기준으로 분할한다.
2. 분할된 두 부분에 재귀 호출을 수행한다.
3. 분할이 균등하면 O(n log n), 불균등하면 O(n²)이 될 수 있다.

또한 퀵 정렬 문제에서 특정 단계의 배열 상태를 물어본다면 피벗 선택 방식과 partition 구현 방식을 반드시 확인해야 한다. 분할 방법이 다르면 중간 배열 상태가 달라질 수 있기 때문이다.

## 5. 기수 정렬(Radix Sort)

### 기수 정렬이란?

**기수 정렬(Radix Sort)**은 데이터의 값을 직접 비교하지 않고, 숫자의 각 자릿수를 기준으로 데이터를 분배하여 정렬하는 알고리즘이다.

선택 정렬, 삽입 정렬, 퀵 정렬은 두 원소를 비교하여 순서를 결정하지만 기수 정렬은 자릿수별로 데이터를 분류하는 방식을 사용한다.

기수 정렬에서는 데이터를 분류하기 위해 **버킷(Bucket)**을 사용한다.

10진수 정렬이라면 각 자릿수는 0부터 9까지이므로 10개의 버킷이 필요하다.

### 기수 정렬의 기본 원리

예를 들어 `[8, 2, 7, 3, 5]`를 정렬한다고 가정하자.

각 숫자를 해당하는 번호의 버킷에 넣는다.

- 8 → 8번 버킷
- 2 → 2번 버킷
- 7 → 7번 버킷
- 3 → 3번 버킷
- 5 → 5번 버킷

이후 0번부터 9번 버킷까지 순서대로 원소를 꺼내면

`[2, 3, 5, 7, 8]`

이 된다.

원소를 서로 비교하지 않고도 정렬할 수 있다.

### 여러 자릿수의 정렬

여러 자릿수의 자연수를 정렬할 때는 낮은 자릿수부터 높은 자릿수 순서로 정렬한다.

예를 들어 `[28, 93, 39, 81, 62, 72, 38, 26]`을 정렬해보자.

1단계: 1의 자리 기준 정렬

`[81, 62, 72, 93, 26, 28, 38, 39]`

2단계: 10의 자리 기준 정렬

`[26, 28, 38, 39, 62, 72, 81, 93]`

최종적으로 오름차순 정렬이 완료된다.

![1의 자리와 10의 자리 순서로 정렬하는 기수 정렬](/assets/img/posts/sorting-chapter6/radix-sort-passes.png)
{: .study-diagram }

이처럼 낮은 자릿수부터 정렬하는 방식을 LSD(Least Significant Digit) 방식이라고 한다.

### 왜 낮은 자릿수부터 정렬할까?

높은 자릿수가 최종적인 숫자의 크기를 결정하기 때문이다.

먼저 낮은 자릿수로 정렬한 다음 높은 자릿수로 정렬하면, 높은 자릿수가 같은 원소들 사이에서는 앞서 정렬된 낮은 자릿수의 순서가 유지된다.

따라서 각 단계에서 안정성이 보장되어야 한다.

### 버킷에 큐를 사용하는 이유

기수 정렬에서는 같은 버킷에 들어간 데이터들의 상대적인 순서를 유지해야 한다.

따라서 먼저 들어간 데이터가 먼저 나오는 FIFO(First In First Out) 구조가 필요하다.

예를 들어 `[28, 38, 93]`을 1의 자리로 분배하면 93은 3번 버킷에, 28과 38은 차례대로 8번 버킷에 들어간다. 버킷을 순서대로 비우면 `[93, 28, 38]`이 되며, 8번 버킷에 들어간 28과 38의 순서는 유지된다.

![1의 자리 버킷에서 28과 38의 입력 순서가 유지되는 기수 정렬](/assets/img/posts/sorting-chapter6/radix-bucket-fifo.png)
{: .study-diagram }

이를 위해 큐(Queue)를 사용한다.

- `enqueue`: 해당 자릿수에 맞는 버킷에 삽입
- `dequeue`: 버킷에서 순서대로 꺼내기

Python에서는 `collections.deque`를 사용할 수 있다.

- `append(x)`: 큐의 뒤에 데이터 삽입
- `popleft()`: 큐의 앞에서 데이터 제거

### 기수 정렬 구현

```python
from collections import deque

def radix_sort(A):
    BUCKETS = 10
    queues = [deque() for _ in range(BUCKETS)]

    if not A:
        return A

    max_value = max(A)
    factor = 1

    while max_value // factor > 0:
        for num in A:
            digit = (num // factor) % BUCKETS
            queues[digit].append(num)

        i = 0
        for bucket in queues:
            while bucket:
                A[i] = bucket.popleft()
                i += 1

        factor *= BUCKETS

    return A
```

위 코드는 **0 이상의 정수**를 대상으로 한다. 음수를 포함한 정렬에는 별도 처리가 필요하다.

**코드의 핵심**

- `BUCKETS = 10`: 10진수이므로 버킷 10개 사용
- `factor = 1`: 1의 자리부터 정렬 시작
- `(num // factor) % 10`: 현재 자릿수 추출
- `queues[digit].append(num)`: 해당 버킷에 삽입
- `bucket.popleft()`: 버킷의 데이터를 순서대로 꺼냄
- `factor *= 10`: 다음 자릿수로 이동

### 자릿수 추출 방법

기수 정렬에서 가장 중요한 연산은 다음과 같다.

`(num // factor) % 10`

예를 들어 `num = 1234`라면 다음과 같다.

| factor | 계산 | 추출되는 자릿수 |
| --- | --- | --- |
| 1 | `(1234 // 1) % 10` | 4 |
| 10 | `(1234 // 10) % 10` | 3 |
| 100 | `(1234 // 100) % 10` | 2 |
| 1000 | `(1234 // 1000) % 10` | 1 |

`//`는 정수 나눗셈, `%`는 나머지 연산이다.

### 기수 정렬의 시간 복잡도

기수 정렬에서는 모든 데이터를 각 자릿수마다 한 번씩 버킷에 넣고 다시 꺼낸다.

입력 데이터 개수를 n, 최대 자릿수를 d라고 하면 **O(dn)** 으로 표현할 수 있다. 단, 버킷 수를 일정하게 고정한 경우이다.

버킷 수를 b까지 포함하여 일반화하면 **O(d(n+b))**이다.

| 항목 | 복잡도 |
| --- | --- |
| 시간 복잡도 | O(d(n+b)) |
| 버킷 수 b가 상수일 때 | O(dn) |
| 추가 공간 복잡도 | O(n+b) |

최대 자릿수 d가 작고 일정하다면 n에 비례하는 시간에 정렬할 수 있다.

### 기수 정렬의 특징

- 비교 연산 없이 정렬할 수 있다.
- 자릿수를 이용하므로 적용할 수 있는 데이터 형태에 제약이 있다.
- 안정적인 버킷 처리를 사용하면 안정 정렬이다.
- 추가적인 버킷 메모리가 필요하다.
- 자릿수가 적고 데이터가 많을 때 효율적일 수 있다.
- 자릿수가 매우 크거나 정렬 키의 형태가 적합하지 않다면 비효율적일 수 있다.

💡 코테 포인트

기수 정렬에서 기억해야 할 핵심은 자릿수 추출, 큐, 안정성이다.

특히 `factor *= 10`을 이용해 1의 자리부터 10의 자리, 100의 자리 순서로 이동하는 원리를 이해해야 한다.

## 6. 파이썬의 정렬 함수 활용하기

코딩테스트에서는 정렬 알고리즘을 직접 구현하는 문제도 있지만, 일반적인 정렬 문제에서는 Python의 내장 정렬 기능을 사용하는 경우가 많다.

대표적인 방법은 `list.sort()`와 `sorted()`이다.

### 리스트의 sort() 메서드

`sort()`는 기존 리스트 자체를 정렬한다.

```python
data = [6, 3, 7, 4, 9, 1, 5, 2, 8]

data.sort()
print(data)  # [1, 2, 3, 4, 5, 6, 7, 8, 9]

data.sort(reverse=True)
print(data)  # [9, 8, 7, 6, 5, 4, 3, 2, 1]
```

`sort()`는 기존 리스트를 직접 변경하며 반환값은 `None`이다.

따라서 `result = data.sort()`처럼 작성하면 `result`에 정렬된 리스트가 저장되는 것이 아니라 `None`이 저장된다.

### sorted() 함수

`sorted()`는 정렬된 새로운 리스트를 반환한다.

```python
data = [6, 3, 7, 4, 9, 1, 5, 2, 8]

result = sorted(data)

print(result)  # [1, 2, 3, 4, 5, 6, 7, 8, 9]
print(data)    # [6, 3, 7, 4, 9, 1, 5, 2, 8]
```

기존 데이터의 순서를 유지해야 한다면 `sorted()`를 사용하면 된다.

### sort()와 sorted() 비교

| 구분 | `sort()` | `sorted()` |
| --- | --- | --- |
| 사용 형태 | `data.sort()` | `sorted(data)` |
| 원본 변경 | O | X |
| 반환값 | `None` | 정렬된 새 리스트 |
| 사용 대상 | 리스트 | 반복 가능한 객체 |
| 내림차순 | `reverse=True` | `reverse=True` |
| 정렬 기준 지정 | `key=` | `key=` |

💡 코테 포인트

- 원본을 변경해도 된다면 `sort()`
- 원본을 유지해야 한다면 `sorted()`
- 내림차순이면 `reverse=True`
- 특정 조건으로 정렬하려면 `key=`

### 복잡한 레코드 정렬하기

정렬할 데이터가 단순한 숫자가 아니라 여러 필드를 가진 레코드라면 정렬 기준을 지정해야 한다.

예를 들어 다음과 같은 좌표 데이터가 있다고 가정하자.

`data = [(3, 5, 2), (1, 7, 4), (2, 3, 6)]`

각 튜플은 `(x, y, z)`를 의미한다.

x좌표를 기준으로 오름차순 정렬하고 싶다면 다음과 같이 작성한다.

`sorted(data, key=lambda p: p[0])`

결과는

`[(1, 7, 4), (2, 3, 6), (3, 5, 2)]`

이다.

### 람다 함수(Lambda)

**람다 함수(Lambda Function)**는 이름 없이 간단한 함수를 한 줄로 작성하는 방법이다.

기본 형태는 다음과 같다.

`lambda 인자: 반환할 식`

예를 들어

`lambda p: p[0]`

은 입력받은 `p`의 첫 번째 원소를 반환한다.

이를 `key`에 전달하면 정렬할 때 각 원소의 첫 번째 값을 기준으로 비교한다.

### 정렬 기준 지정하기

| 정렬 기준 | 코드 |
| --- | --- |
| 첫 번째 값 오름차순 | `sorted(data, key=lambda x: x[0])` |
| 두 번째 값 오름차순 | `sorted(data, key=lambda x: x[1])` |
| 두 번째 값 내림차순 | `sorted(data, key=lambda x: x[1], reverse=True)` |
| 문자열 길이순 | `sorted(words, key=len)` |
| 절댓값순 | `sorted(nums, key=abs)` |
| 좌표의 제곱 크기순 | `sorted(data, key=lambda p: p[0]**2 + p[1]**2 + p[2]**2)` |

좌표의 크기를 기준으로 정렬할 때는 원점으로부터의 거리를 사용할 수 있다.

$$
r=\sqrt{x^2+y^2+z^2}
$$

단순히 거리의 크기를 비교하는 목적이라면 제곱근을 계산하지 않고 `x²+y²+z²`를 기준으로 정렬해도 같은 결과를 얻을 수 있다.

### 여러 조건으로 정렬하기

코딩테스트에서는 하나의 조건이 아니라 여러 조건을 동시에 적용해야 하는 문제가 자주 등장한다.

예를 들어 학생 정보를 `(이름, 점수)` 형태로 저장했다고 가정하자.

`students = [('철수', 90), ('영희', 80), ('민수', 90)]`

조건: 점수 내림차순, 점수가 같다면 이름 오름차순

```python
students.sort(key=lambda x: (-x[1], x[0]))
```

결과는

`[('민수', 90), ('철수', 90), ('영희', 80)]`

이다.

핵심 원리

- `-x[1]`: 점수를 내림차순으로 정렬
- `x[0]`: 점수가 같다면 이름을 오름차순으로 정렬
- 튜플의 첫 번째 조건부터 비교하고 같으면 다음 조건으로 넘어감

💡 코테 포인트

`reverse=True`는 정렬 결과의 전체 순서를 뒤집는 것이므로 한 조건은 내림차순, 다른 조건은 오름차순으로 정렬해야 한다면 `key`에 튜플을 사용하는 방식이 유용하다.

### 파이썬의 정렬 알고리즘: 팀 정렬(Timsort)

Python의 `sort()`와 `sorted()`는 **팀 정렬(Timsort)**을 사용한다.

팀 정렬은 삽입 정렬과 병합 정렬의 장점을 결합한 하이브리드 정렬 알고리즘이다.

입력 데이터에서 이미 정렬된 구간을 찾아 활용하며, 작은 구간에는 삽입 정렬을 적용하고 정렬된 구간들을 병합하는 방식으로 동작한다.

이때 정렬된 데이터의 연속 구간을 **런(Run)**이라고 한다.

팀 정렬은 이미 정렬된 구간을 활용하므로 실제 데이터에서 높은 효율성을 보일 수 있다.

| 경우 | 시간 복잡도 |
| --- | --- |
| 최선 | O(n) |
| 평균 | O(n log n) |
| 최악 | O(n log n) |

또한 안정 정렬이라는 특징이 있다.

따라서 코딩테스트에서 단순히 정렬된 결과가 필요하다면 직접 퀵 정렬 등을 구현하기보다는 Python의 내장 정렬 기능을 사용하는 것이 일반적으로 효율적이다.

## 7. 정렬 알고리즘 비교 및 코딩테스트 핵심 정리

## 정렬 알고리즘 비교

| 알고리즘 | 최선 | 평균 | 최악 | 안정성 | 제자리 정렬 |
| --- | --- | --- | --- | --- | --- |
| 선택 정렬 | O(n²) | O(n²) | O(n²) | X | O |
| 삽입 정렬 | O(n) | O(n²) | O(n²) | O | O |
| 퀵 정렬 | O(n log n) | O(n log n) | O(n²) | X | O* |
| 기수 정렬 | O(d(n+b)) | O(d(n+b)) | O(d(n+b)) | O** | X |
| 팀 정렬 | O(n) | O(n log n) | O(n log n) | O | X*** |

* 퀵 정렬은 재귀 호출 스택이 필요하다. 
** 기수 정렬은 안정적인 버킷 처리를 사용하는 경우이다. 
*** Python의 팀 정렬은 보조 메모리를 사용할 수 있다. n은 원소 수, d는 자릿수, b는 버킷 수이다.

## 코딩테스트에서 기억할 내용

### 1. 정렬 알고리즘의 핵심 원리 구분하기

| 알고리즘 | 핵심 원리 |
| --- | --- |
| 선택 정렬 | 최솟값을 선택하여 앞쪽 원소와 교환 |
| 삽입 정렬 | 현재 값을 정렬된 부분의 알맞은 위치에 삽입 |
| 퀵 정렬 | 피벗을 기준으로 분할하고 재귀적으로 정렬 |
| 기수 정렬 | 자릿수에 따라 버킷에 분배 |
| 팀 정렬 | 정렬된 구간을 활용하여 삽입·병합 정렬 결합 |

### 2. 입력 데이터의 상태에 따른 성능 차이 이해하기

선택 정렬은 데이터가 이미 정렬되어 있어도 O(n²)이 필요하다.

삽입 정렬은 이미 정렬된 경우 O(n)으로 처리할 수 있다.

퀵 정렬은 피벗 선택에 따라 O(n log n) 또는 O(n²)이 될 수 있다.

따라서 정렬 알고리즘의 성능은 단순히 입력 크기뿐만 아니라 데이터가 어떤 순서로 배치되어 있는지에 따라서도 달라진다.

### 3. 정렬 문제에서 key와 lambda 활용하기

Python 코딩테스트에서는 직접 정렬 알고리즘을 구현하는 것보다 정렬 조건을 올바르게 작성하는 능력이 중요할 때가 많다.

특히 다음 형태를 익혀두면 유용하다.

- `data.sort()`: 오름차순
- `data.sort(reverse=True)`: 내림차순
- `sorted(data)`: 원본을 유지하면서 정렬
- `sorted(data, key=lambda x: x[1])`: 두 번째 값을 기준으로 정렬
- `sorted(data, key=lambda x: (-x[1], x[0]))`: 여러 조건을 조합하여 정렬

### 4. 안정 정렬이 필요한 상황 이해하기

여러 조건을 단계적으로 정렬할 때는 같은 키를 가진 원소의 순서가 유지되는지가 중요하다.

Python의 `sort()`와 `sorted()`는 안정 정렬이므로 같은 키를 가진 데이터들의 상대적인 순서가 유지된다.

### 5. 정렬 과정 추적 문제 해결하기

선택 정렬, 삽입 정렬, 퀵 정렬, 기수 정렬은 중간 단계의 결과를 묻는 문제가 나올 수 있다.

이때 각 알고리즘에서 한 단계가 의미하는 작업이 다르다는 점에 주의해야 한다.

| 알고리즘 | 한 단계에서 하는 작업 |
| --- | --- |
| 선택 정렬 | 정렬되지 않은 부분의 최솟값 선택 및 교환 |
| 삽입 정렬 | 원소 하나를 정렬된 부분에 삽입 |
| 퀵 정렬 | 피벗을 기준으로 부분 리스트 분할 |
| 기수 정렬 | 특정 자릿수를 기준으로 전체 데이터 분류 |

특히 퀵 정렬은 피벗 선택 방식과 분할 방법에 따라 중간 결과가 달라지므로 문제의 조건을 정확하게 확인해야 한다.

## Chapter 06 핵심 요약

정렬(Sorting)
→ 데이터를 일정한 기준에 따라 순서대로 재배열하는 작업

레코드(Record)
→ 정렬 대상이 되는 하나의 데이터

필드(Field)
→ 레코드를 구성하는 개별 속성

키(Key)
→ 정렬의 기준이 되는 필드

안정 정렬(Stable Sort)
→ 동일한 키를 가진 원소들의 상대적인 순서 유지

제자리 정렬(In-place Sorting)
→ 입력 배열 외에 추가적인 배열을 사용하지 않는 정렬

선택 정렬(Selection Sort)
→ 최솟값을 찾아 앞쪽 원소와 교환
→ 최선·평균·최악 O(n²)
→ 불안정 정렬, 제자리 정렬

삽입 정렬(Insertion Sort)
→ 정렬된 부분에 새로운 원소를 삽입
→ 최선 O(n), 평균·최악 O(n²)
→ 안정 정렬, 제자리 정렬

퀵 정렬(Quick Sort)
→ 피벗을 기준으로 분할하고 재귀적으로 정렬
→ 평균 O(n log n), 최악 O(n²)
→ 분할 정복, 불안정 정렬

기수 정렬(Radix Sort)
→ 자릿수에 따라 버킷에 분배
→ O(d(n+b))
→ 안정적인 버킷 처리를 사용하며 추가 메모리 필요

Python 정렬 함수

- `sort()` → 원본 리스트 변경
- `sorted()` → 정렬된 새 리스트 반환
- `reverse=True` → 내림차순
- `key=` → 정렬 기준 지정
- `lambda` → 간단한 정렬 기준 함수 작성

팀 정렬(Timsort)
→ Python 내장 정렬 알고리즘
→ 삽입 정렬과 병합 정렬을 결합
→ 최악 O(n log n), 안정 정렬

6장의 핵심 흐름은 정렬의 개념과 특성 이해 → 선택·삽입·퀵·기수 정렬의 작동 원리 파악 → 각 알고리즘의 시간 복잡도 비교 → Python의 `sort()`, `sorted()`, `key`, `lambda`를 활용한 정렬 문제 해결이다.

특히 코딩테스트에서는 정렬 알고리즘의 원리와 시간 복잡도를 이해하는 것, 정렬 과정을 직접 추적할 수 있는 것, 여러 정렬 조건을 Python 코드로 정확하게 구현하는 것이 중요하다.
